## Java projects
-   **Jackson Dependency Alignment (`StreamReadConstraints`)**:
    - Apache Beam 2.50+ requires Jackson 2.15+ (`jackson-core`, `jackson-databind`, `jackson-annotations`).
    - Older versions of `jackson-core` pulled transitively miss `com.fasterxml.jackson.core.StreamReadConstraints` and cause `NoClassDefFoundError` at runtime.
    - In `pom.xml`, you MUST explicitly declare all three Jackson artifacts (`com.fasterxml.jackson.core:jackson-core`, `com.fasterxml.jackson.core:jackson-databind`, `com.fasterxml.jackson.core:jackson-annotations`) with version `2.15.3` (or `2.15.2`).
-   **SLF4J Logging Dependency Alignment**:
    -   Verify the `slf4j-api` version pulled transitively by Apache Beam.
    -   You MUST configure the application logging backend (`slf4j-simple`,
        `logback-classic`, etc.) to exactly match the major/minor version of the
        resolved `slf4j-api`.
-   **Testing Dependencies (`SerializableMatcher` & `TestRule`)**:
    - Apache Beam's `TestPipeline` and `PAssert` implement JUnit 4's `TestRule` and use Hamcrest matchers (`SerializableMatcher`).
    - In `pom.xml`, you MUST include `junit:junit:4.13.2`, `org.hamcrest:hamcrest:2.2`, `org.hamcrest:hamcrest-library:2.2`, and `org.junit.vintage:junit-vintage-engine:${junit.version}` under `<scope>test</scope>`. Missing `junit:junit` or `hamcrest` causes `java.lang.NoClassDefFoundError: org/apache/beam/sdk/testing/SerializableMatcher` or `cannot access org.junit.rules.TestRule`.
-   **Coder for Maps / Generic Objects**:
    - Apache Beam Java cannot infer a default `Coder` for `Map<String, Object>` or generic `Object`.
    - Avoid returning `PCollection<Map<String, Object>>` without an explicit coder. When returning custom maps or objects, set `.setCoder(KvCoder.of(...))` or `.setCoder(SerializableCoder.of(...))` explicitly, or use Beam `Row` schema (`PCollection<Row>`).

## Packaging a pipeline as a Flex Template

Flex Templates offer a hermetic and reproducible launch environment for a
pipeline. They are easy to launch with `gcloud` or with orchestrators like Cloud
Composer. You **MUST** package the pipeline as a Flex Template when creating new
Dataflow pipeline projects.

Follow the steps below:

-   **Provide Instructions**: Provide instructions on rebuilding and running
    Flex Templates to the user in the Readme.md file.
-   **Use Single Docker Image for Python pipelines**: For Python Flex Templates,
    it is better to use a single image for the template launcher image and for
    the worker runtime environment (`--sdk_container_image`). Does the Python
    pipeline require extra dependencies (e.g., using `--requirements_file`,
    `--setup_file`, or `--extra_package`)? If so, **YOU MUST recommend the**
    **Single Docker Image Configuration** for the Flex Template. See
    [python_flex_template_reference.md][py-flex-ref] for details.
-   **Python Dockerfile Configuration**:
    -   When generating a Dockerfile for a Python Flex Template, you MUST set the environment variable `FLEX_TEMPLATE_PYTHON_PY_FILE` to point to the absolute path of the main Python script inside the container (e.g. `ENV FLEX_TEMPLATE_PYTHON_PY_FILE="/template/src/pipeline.py"` or wherever the pipeline code is copied). Do NOT use `FLEX_TEMPLATE_PYTHON_MAIN_FILE` or any other environment variable name, as the standard launcher base image strictly requires `FLEX_TEMPLATE_PYTHON_PY_FILE` to determine the script to execute.
-   **Prefer Cloud Build over Local Docker**:
    -   Do NOT assume local Docker availability on the workspace machine.
    -   **Action**: Suggest and provide `cloudbuild.yaml` out-of-the-box for
        building and pushing images unless local setup is explicitly requested.
    -   When building images with Cloud Build in the background you MUST provide
        the link where the user can monitor the long-running operation.
-   **Providing SSL certificates and Secrets to Workers**:
    -   If certificates or keys are stored in Secret Manager, **NEVER** bake
        them into the Docker image layers. Instead, retrieve them dynamically at
        runtime inside the Apache Beam `DoFn.setup()` lifecycle using the Secret
        Manager client library (writing them to ephemeral worker disk like
        `/tmp` only if physical file paths are strictly required). Ensure the
        Dataflow Worker Service Account has the
        `roles/secretmanager.secretAccessor` role.
