## Credential Handling Rules (GLOBAL - applies to every transform)

Credentials are never stored inline in the pipeline definition. A node configures
authentication in one of two ways, and you MUST inspect each node's properties to tell
them apart:

1. **Secret Manager reference (preferred).** The node has `authMode: secretManager` and/or
   a property whose name ends in `Secret` -- for example `passwordSecret`,
   `accessKeySecret` -- or a `secretName` property. The VALUE of that property is the
   SHORT ID of a Google Cloud Secret Manager secret. It is NOT the credential.
   - You MUST generate code that resolves the secret at runtime.
   - Required import: `com.google.cloud.secretmanager.v1.SecretManagerServiceClient`,
     `com.google.cloud.secretmanager.v1.SecretVersionName`
   - Required Maven dependency:
     ```xml
     <dependency>
       <groupId>com.google.cloud</groupId>
       <artifactId>google-cloud-secretmanager</artifactId>
     </dependency>
     ```
     (the `libraries-bom` already manages its version if present; otherwise pin one)
   - Resolve the secret ONCE at pipeline construction time, in `main`, never inside a
     `DoFn`. A `DoFn` runs per element and per worker, and `SecretManagerServiceClient`
     is not serializable -- fetching there would both break serialization and issue one
     API call per record.
   - Use this shape:
     ```java
     /** Reads the payload of a Secret Manager secret. */
     private static String accessSecret(String projectId, String secretId) throws IOException {
       try (SecretManagerServiceClient client = SecretManagerServiceClient.create()) {
         SecretVersionName name = SecretVersionName.of(projectId, secretId, "latest");
         return client.accessSecretVersion(name).getPayload().getData().toStringUtf8();
       }
     }
     ```
   - Assign the resolved value to a `final String` local in `main` and pass that into the
     transform where the plaintext property would otherwise have gone. For example, a
     JdbcIO node with `passwordSecret: prod-db-pw` becomes
     `.withPassword(accessSecret(projectId, "prod-db-pw"))`.
   - Derive `projectId` from the pipeline options (`options.getProject()`). Do NOT hardcode it.

2. **Pipeline Options / Parameterized Credentials (when credentials exist in YAML properties)**:
   - **CRITICAL ZERO-PLAINTEXT MANDATE**: NEVER embed plaintext database passwords, connection secrets, auth tokens, or private keys as string literals in Java source code or `DataSourceConfiguration` calls (e.g. NEVER write `.withPassword("dbpswrd123")` or `.withUsername("dbuser123")`).
   - **NO DEFAULT VALUE ANNOTATIONS ON PASSWORDS**: NEVER use `@Default.String(...)` or any default value annotation for sensitive password options in the `PipelineOptions` interface. Secrets must NOT have hardcoded defaults in the code.
   - When a node specifies authentication properties (such as `password`, `username`, or connection strings) directly in YAML without a `*Secret` reference:
     - **Parameterize via `PipelineOptions`**: Expose these credential properties as configurable options in the custom `PipelineOptions` interface without default annotations (e.g., `String getSourceDbUsername(); void setSourceDbUsername(String value);`, `String getSourceDbPassword(); void setSourceDbPassword(String value);`, and similarly for sink nodes, e.g. `String getSinkDbUsername(); void setSinkDbUsername(String value);`, `String getSinkDbPassword(); void setSinkDbPassword(String value);`, or `getDbUsername()` / `getDbPassword()` if a single DB).
     - Pass the values from `options` into the transform (e.g. `.withUsername(options.getSourceDbUsername()).withPassword(options.getSourceDbPassword())`).
      - Declare the corresponding parameters in `metadata.json` under `parameters` (marked `"isOptional": false`, and always specify `"isSecret": true` in addition to `"isOptional": false` for any credential, password, token, or private key parameter to ensure sensitive values are masked in Dataflow UI and execution logs).
      - **NO FALLBACK STRINGS IN RUNNER SCRIPTS**: Do NOT include hardcoded fallback strings for sensitive passwords or tokens in runner shell scripts (e.g. NEVER write `PASSWORD=${PASSWORD:-'dbpswrd123'}`). Instead, check for the required environment variable, exiting with an error if unset:
        ```bash
        : "${SOURCE_DB_PASSWORD:?Error: SOURCE_DB_PASSWORD environment variable must be set}"
        ```
        Then pass `--sourceDbPassword="${SOURCE_DB_PASSWORD}"` (usernames or non-sensitive identifiers can use standard fallbacks like `${SOURCE_DB_USERNAME:-dbuser123}`).
      - This rule is an explicit exception to the "only runtimeVariables in PipelineOptions" rule: sensitive credentials MUST be parameterized via `PipelineOptions` to ensure zero plaintext secrets in code and scripts.

**MUTUAL EXCLUSION**: never emit both. If a node has a `*Secret` reference, ignore any
plaintext property of the same name and use the Secret Manager path.

**REDACTED VALUES**: if a property value is exactly `__REDACTED_BY_BEAM_DESIGNER__`, that is
a placeholder, not a credential. Never emit it as a string literal. Read the value from an
environment variable named after the property in upper snake case via `System.getenv(...)`
and add a brief comment noting that the operator must supply it.

## 3. Core Architecture & Coding Rules

### A. Runtime Variables vs. Hardcoded Node Configuration
- **RUNTIME VARIABLES & SENSITIVE CREDENTIAL PARAMETERIZATION**:
  - `PipelineOptions`, `metadata.json`, and runner scripts MUST include:
    1. All variables explicitly declared under `runtimeVariables` in the YAML (e.g. `JOB_ID`, `NUM_OBJECTS_PER_ITERATION`).
    2. Any sensitive credentials (such as JDBC database passwords and usernames) present in node properties, parameterized as described in the Credential Handling Rules above.
  - **DEPLOYMENT-VARYING PROPERTIES MUST BE RUNTIME OPTIONS**: A generated pipeline is packaged as a Dataflow Flex Template, so any property an operator would reasonably change between runs of the *same built artifact* MUST be exposed on the `PipelineOptions` interface with the YAML value supplied via `@Default.String(...)`, and MUST also appear as a parameter in `metadata.json`. This category is:
    1. **Input locations** — `filePattern`, `from`, and any other source path or glob.
    2. **Output locations** — `to`, output path prefixes, and destination directories.
    3. Everything declared under `runtimeVariables` (see above).
    4. Sensitive credentials (see the Credential Handling Rules above).
    Requiring a rebuild to repoint a template at a different input or output path defeats the purpose of a template, so these are never hardcoded.
  - **HARDCODE EVERYTHING ELSE**: All remaining non-sensitive node configuration — JDBC driverClassName, SQL queries, table names, fetch/batch sizes, delimiters, charsets, compression codecs, shard counts, window durations, BigQuery tables, Pub/Sub topics, Kafka topics and queue URLs — MUST be hardcoded directly into the transform calls. These describe what the pipeline *is*, not where a given run reads and writes, and exposing them as options bloats the template surface. NEVER hardcode passwords or sensitive credentials directly in code.
- **Reserved Option Name Safety & Remapping**:
  - **NEVER use reserved Beam option names**: `jobId`, `jobName`, `project`, `tempLocation`, `gcpTempLocation`, `runner`, `appName` are reserved by Apache Beam / Dataflow. Declaring `getJobId()` in a custom `PipelineOptions` interface causes fatal `IllegalArgumentException: Expected getter for property [jobId] to be marked with @Default on all ... DataflowWorkerHarnessOptions`.
  - If a runtime variable is named `JOB_ID` or `job_id`, map its identifier to `pipelineJobId` consistently across ALL artifacts:
    - `PipelineOptions` interface: `String getPipelineJobId(); void setPipelineJobId(String value);`
    - `metadata.json` parameter `"name"`: `"pipelineJobId"`
    - `run_directrunner.sh` arguments: `--pipelineJobId="value"`
    - `run_sparkrunner.sh` arguments: `--pipelineJobId="value"`
    - `run_dataflowrunner.sh` parameters: `pipelineJobId="value"`
  - Convert all other runtime variables from YAML into standard camelCase (e.g. `NUM_OBJECTS_PER_ITERATION` -> `numObjectsPerIteration`, getter: `getNumObjectsPerIteration()`, setter: `setNumObjectsPerIteration(Integer value)`).
  - Use standard typed getters/setters on `PipelineOptions`. Do NOT use `ValueProvider<T>` (deprecated legacy Classic template API).
  - Ensure that ALL runtime variables defined in YAML are supplied with default values in `run_directrunner.sh`, `run_dataflowrunner.sh`, and `run_sparkrunner.sh`.

### B. Node Instruction Fields vs Hardcoded Config
- `data.system_instructions` and `data.properties.codeGenerationPrompt` (or `data.properties.prompt`) contain natural-language descriptions of the logic this node must implement.
  - Treat them as implementation instructions: generate Java code that fulfills them.
  - NEVER emit them as string literals, configuration values, or comment-only stubs.
  - They are EXEMPT from the "hardcode all node properties" rule.
  - If they conflict with default behaviors in the reference table below, the node's instructions win.
- **NO SCHEMA GUESSING / HALLUCINATION**: Do NOT invent, assume, or hardcode payload schema fields based on topic, subscription, dataset, or table names (for example, do NOT assume a subscription named with "object-finalize" carries specific GCS file metadata keys like `bucket`, `name`, `size`, `timeCreated`). Unless explicit schema fields are specified in `system_instructions` or `codeGenerationPrompt`, ALWAYS parse payloads generically across all fields.

### C. Runtime Variable Interpolation
- Any `${VAR_NAME}` token inside a node's properties or instructions refers to the runtime variable `VAR_NAME` from `runtimeVariables`.
- Replace it with a read of the corresponding `PipelineOptions` getter using camelCase (e.g. `${NUM_OBJECTS_PER_ITERATION}` -> `options.getNumObjectsPerIteration()`). NEVER hardcode the default value of an interpolated `${VAR_NAME}`.

### D. Custom `DoFn` Policy
- **PREFER BUILT-IN TRANSFORMS**: If a node's `beam_transform` appears in the SDK Syntax Reference below, use that built-in `PTransform`. Do NOT reimplement it as a custom `DoFn`.
- **WHEN A CUSTOM `DoFn` IS REQUIRED**: Write a custom `DoFn` ONLY in these cases:
  1. `beam_transform` is `ParDo` or `ParseMessage` (multi-output branching parser).
  2. The node has `system_instructions` or `codeGenerationPrompt` describing custom business logic.
  3. A built-in transform requires a user-supplied function argument (`Filter.by`, `MapElements.via`, `WithKeys.of`, `JdbcIO.PreparedStatementSetter`/`RowMapper`), or type adaptation is needed between two built-ins.
- Define custom `DoFn` classes as `static` nested classes inside the main pipeline class, or as concise inline lambdas. Do NOT create separate helper source files.

### E. Type Propagation & End-to-End Edge Compatibility
- **MANDATORY EDGE TYPE ALIGNMENT**: Every edge in the input YAML connects a `source` node to a `target` node. When generating code, you MUST inspect both:
  1. **Upstream Output Type ($T_{in}$)**: The Java type emitted by the predecessor node (see Section 4).
  2. **Downstream Expected Input Type ($T_{out}$)**: The Java type consumed by the successor node (see Section 4).
- **Intermediate Transform Bridging**: Any intermediate step (`ParseMessage`, `ParDo`, `Map`, `Filter`) MUST explicitly bridge $T_{in} \rightarrow T_{out}$ to match the downstream connector's expected input type as defined in Section 4. (For example, BigQuery sinks require `TableRow`, Kafka sinks require `KV<K, V>`, Parquet sinks require `GenericRecord`, Text/PubSub sinks require `String`, etc.).
- **Automatic Adapters for Direct Incompatible Edges**: If an edge in the YAML directly connects a source to a sink with incompatible types without an intermediate transformation (e.g. `PubsubIO.readStrings()` producing `String` connected directly to `BigQueryIO.writeTableRows()` requiring `TableRow`), you MUST automatically insert a clean mapping step (such as `MapElements` converting `String` to `TableRow`) between them so the Java pipeline is strictly type-safe and compilable.

### F. Transform Naming & Uniqueness
- Every step name in `.apply("<step_name>", ...)` MUST be non-empty and **globally unique** across the pipeline.
- Use `data.label` as the step name. If multiple nodes share the same label or if the label equals the default transform name, append a distinct qualifier or node ID (e.g. `Filter Valid Records (node_2)`) to prevent `IllegalArgumentException: A transform with name '...' already exists in the pipeline`.

### G. Streaming vs. Batch Detection
- If the pipeline contains streaming sources (`PubsubIO`, `KafkaIO`, `MqttIO`, `PeriodicImpulse`, unbounded `GenerateSequence`), configure the pipeline for streaming:
  - Pass `--streaming=true` in `run_directrunner.sh`.
  - When creating `PipelineOptions`, ensure streaming options can be configured.

### H. Separation of Runner Scripts and Unit Tests
- `run_directrunner.sh`, `run_dataflowrunner.sh`, and `run_sparkrunner.sh` MUST ONLY execute the main pipeline class. They must **NEVER** run unit tests (`mvn test`).
- Unit tests live strictly in `src/test/java/com/example/<PipelineName>Test.java` and use Beam's `TestPipeline` and `PAssert`.

### I. Code Documentation & Quality
- Include author and class documentation header on the main class:
  ```java
  /**
   * Pipeline: <PipelineName>
   * Description: <Pipeline Description>
   * Author: Mike Nimer <mikenimer@google.com>
   */
  ```
- Fail fast: Do NOT add undocumented fallbacks or silently swallow exceptions.

## 4. Built-in Beam Transform Syntax & Import Reference

### 1. Sources & Sinks (I/O Connectors)
- **`PubsubIO`**:
  - Required Imports: `org.apache.beam.sdk.io.gcp.pubsub.PubsubIO`
  - Source: `PubsubIO.readStrings().fromTopic(...)` or `PubsubIO.readStrings().fromSubscription(...)`
  - Sink: `PubsubIO.writeStrings().to(...)`
- **`BigQueryIO`**:
  - Required Imports: `org.apache.beam.sdk.io.gcp.bigquery.BigQueryIO`, `com.google.api.services.bigquery.model.TableRow`
  - Source: `BigQueryIO.readTableRows().from(...)` or `.fromQuery(...)`
  - Sink: `BigQueryIO.writeTableRows().to(tableSpec).withCreateDisposition(BigQueryIO.Write.CreateDisposition.CREATE_NEVER).withWriteDisposition(BigQueryIO.Write.WriteDisposition.WRITE_APPEND)`
  - *Note*: `BigQueryIO.readTableRows()` returns `BigQueryIO.TypedRead<TableRow>`, NOT `TypedRead<String>`.
- **`TextIO`**:
  - Required Imports: `org.apache.beam.sdk.io.TextIO`, `org.apache.beam.sdk.io.Compression`, `org.apache.beam.sdk.io.fs.EmptyMatchTreatment`
  - Source: `TextIO.read().from(filePattern).withSkipHeaderLines(n)` (supports `.withCompression(...)`, `.withEmptyMatchTreatment(...)`, `.withDelimiter(byte[])`)
  - Sink: `TextIO.write().to(destinationPrefix).withSuffix(".txt")` (supports `.withNumShards(...)`, `.withoutSharding()`)
- **`FileIO`**:
  - Required Imports: `org.apache.beam.sdk.io.FileIO`, `org.apache.beam.sdk.io.Compression`, `org.apache.beam.sdk.io.fs.EmptyMatchTreatment`
  - Match Source: `FileIO.match().filepattern(pattern).withEmptyMatchTreatment(EmptyMatchTreatment.ALLOW_IF_WILDCARD)`
  - Read Matches: `FileIO.readMatches()` (produces `PCollection<FileIO.ReadableFile>`)
  - Sink: `FileIO.<T>write().to(destinationDir).withSuffix(...)`
- **`ParquetIO`**:
  - Required Imports: `org.apache.beam.sdk.io.parquet.ParquetIO`, `org.apache.avro.Schema`, `org.apache.avro.generic.GenericRecord`, `org.apache.parquet.hadoop.metadata.CompressionCodecName`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-parquet` and `org.apache.parquet:parquet-avro:1.13.1`.
  - Source: `ParquetIO.read(schema).from(filePattern)` (produces `PCollection<GenericRecord>`)
  - Sink: `FileIO.<GenericRecord>write().via(ParquetIO.sink(schema).withCompressionCodec(CompressionCodecName.SNAPPY)).to(destinationDir).withSuffix(".parquet")`
  - **Avro Schema Parsing (Directive J1)**: When transforming elements into Avro `GenericRecord` instances within a `DoFn` or mapper, parse the Avro Schema string once during initialization (e.g., in `@Setup` or constructor storing a `transient Schema` field), rather than calling `new Schema.Parser().parse(...)` repeatedly inside the per-element `apply`/`processElement` method.
- **`Create`**:
  - Required Imports: `org.apache.beam.sdk.transforms.Create`
  - Source: `Create.of(Arrays.asList(...))`
- **`GenerateSequence`**:
  - Required Imports: `org.apache.beam.sdk.io.GenerateSequence`, `org.joda.time.Duration`
  - Bounded: `GenerateSequence.from(start).to(stop)` (produces `PCollection<Long>`)
  - Unbounded: `GenerateSequence.from(start).withRate(elementsPerPeriod, Duration.standardSeconds(periodSeconds))`
- **`PeriodicImpulse`**:
  - Required Imports: `org.apache.beam.sdk.transforms.PeriodicImpulse`, `org.joda.time.Duration`, `org.joda.time.Instant`
  - Unbounded: `PeriodicImpulse.create().startAt(Instant.now()).withInterval(Duration.standardSeconds(intervalSeconds))`
  - Bounded: `PeriodicImpulse.create().startAt(Instant.now()).stopAt(Instant.now().plus(Duration.standardSeconds(durationSeconds))).withInterval(Duration.standardSeconds(intervalSeconds))`
- **`JdbcIO`**:
  - Required Imports: `org.apache.beam.sdk.io.jdbc.JdbcIO`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-jdbc` plus driver coordinate:
    - PostgreSQL: `org.postgresql:postgresql:42.7.3`
    - MySQL: `com.mysql:mysql-connector-j:8.3.0`
    - SQL Server: `com.microsoft.sqlserver:mssql-jdbc:12.6.1.jre11`
    - Oracle: `com.oracle.database.jdbc:ojdbc11:23.3.0.23.09`
    - SQLite: `org.xerial:sqlite-jdbc:3.45.2.0`
    - Apache Derby: `org.apache.derby:derbyclient:10.16.1.1`
  - Source (Read):
    - When `selectType` is `table` or `tableName` is provided:
      `JdbcIO.readRows().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withTable(tableName)` (where `username` and `password` are resolved from `options` or Secret Manager per Credential Handling Rules, NEVER embedded as hardcoded string literals)
    - When `selectType` is `query` or `query` is provided:
      `JdbcIO.readRows().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withQuery(query)`
    - **Execution Controls (Directive J2)**: If `outputParallelization: true` (or `false`) is configured on a `JdbcIO` source node, append `.withOutputParallelization(true)` (or `false`) to the read transform builder.
  - Sink (Write):
    - `JdbcIO.<T>write().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withStatement(statement).withPreparedStatementSetter((element, preparedStatement) -> { ... })` (where `username` and `password` are resolved from `options` or Secret Manager per Credential Handling Rules, NEVER embedded as hardcoded string literals)
    - **Execution Controls (Directive J2)**: If `autosharding: true` is configured on a `JdbcIO` sink node, append `.withAutoSharding()` to the write transform builder.
    - **CRITICAL SQL & PREPARED STATEMENT SETTER ALIGNMENT RULE**: The SQL statement column list (e.g. `INSERT INTO table (col1, col2) VALUES (?, ?)`) MUST have the exact same number of `?` placeholders as columns. The `PreparedStatementSetter` lambda MUST set every positional parameter 1 through N matching each `?` placeholder in the SQL statement.
- **`KafkaIO`**:
  - Required Imports: `org.apache.beam.sdk.io.kafka.KafkaIO`, `org.apache.kafka.common.serialization.StringDeserializer`, `org.apache.kafka.common.serialization.StringSerializer`, `org.apache.beam.sdk.values.KV`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-kafka` and `org.apache.kafka:kafka-clients:3.6.1`.
  - Source (Read): `KafkaIO.<String, String>read().withBootstrapServers(bootstrapServers).withTopic(topic).withKeyDeserializer(StringDeserializer.class).withValueDeserializer(StringDeserializer.class).withoutMetadata()` (produces `PCollection<KV<String, String>>`). If `groupId` or `kafkaGroupId` is specified in node properties, configure it with `.withConsumerConfigUpdates(ImmutableMap.of(ConsumerConfig.GROUP_ID_CONFIG, groupId))` or `.updateConsumerProperties(Map.of("group.id", groupId))`.
  - Sink (Write): `KafkaIO.<String, String>write().withBootstrapServers(bootstrapServers).withTopic(topic).withKeySerializer(StringSerializer.class).withValueSerializer(StringSerializer.class)`. If `useEOS: true` is specified in node properties, configure exactly-once semantics via `.withEOS(numShards, sinkGroupId)`.
- **`SnsIO`**:
  - Required Imports: `org.apache.beam.sdk.io.aws2.sns.SnsIO`, `software.amazon.awssdk.services.sns.model.PublishRequest`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-amazon-web-services2` and `software.amazon.awssdk:sns:2.25.16`.
  - Sink (Write): `SnsIO.write().to(topicArn)` (payload elements mapped to `PublishRequest`)
  - *Note*: `SnsIO` is write-only. If a node specifies SNS as a source, ingest via an Amazon SQS subscription queue (`SqsIO.read().withQueueUrl(...)`) or bridged GCP Pub/Sub topic (`PubsubIO.readStrings().fromTopic(...)`).
- **`SqsIO`**:
  - Required Imports: `org.apache.beam.sdk.io.aws2.sqs.SqsIO`, `software.amazon.awssdk.services.sqs.model.Message`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-amazon-web-services2` and `software.amazon.awssdk:sqs:2.25.16`.
  - Source (Read): `SqsIO.read().withQueueUrl(queueUrl)` (produces `PCollection<Message>`, body via `message.body()`)
    - **Bounding**: `SqsIO.read()` is UNBOUNDED by default. If `maxNumRecords` is configured on the node, chain `.withMaxNumRecords(long)`; if `maxReadTime` is configured, chain `.withMaxReadTime(org.joda.time.Duration)`. Either one makes the `PCollection` bounded. Note `withMaxReadTime` takes a **Joda** `Duration`, NOT `java.time.Duration`.
  - Sink (Write): `SqsIO.write().withQueueUrl(queueUrl)`
- **`MqttIO`**:
  - Required Imports: `org.apache.beam.sdk.io.mqtt.MqttIO`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-mqtt`.
  - Connection: `MqttIO.ConnectionConfiguration.create(serverUri, topic).withClientId(clientId).withUsername(username).withPassword(password)`
  - Source (Read): `MqttIO.read().withConnectionConfiguration(connConfig)` (produces `PCollection<byte[]>`)
  - Sink (Write): `MqttIO.write().withConnectionConfiguration(connConfig)`
- **`XmlIO`**:
  - Required Imports: `org.apache.beam.sdk.io.xml.XmlIO`, `org.apache.beam.sdk.io.Compression`, `javax.xml.bind.annotation.*`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-xml`. On Java 11+ also add a JAXB 2.x implementation; Beam's XmlIO binds the **`javax.xml.bind`** namespace, so use `jakarta.xml.bind:jakarta.xml.bind-api:2.3.3` (the 2.3.x line still exports `javax.xml.bind`) plus `org.glassfish.jaxb:jaxb-runtime:2.3.3`. JAXB 3.x/4.x export `jakarta.xml.bind` and will NOT work.
  - Source (Read): `XmlIO.<T>read().from(filePattern).withRootElement(root).withRecordElement(record).withRecordClass(T.class)` (also supports `.withCharset(Charset)`, `.withCompression(Compression)`, `.withMinBundleSize(long)`)
  - Sink (Write): `XmlIO.<T>write().to(filenamePrefix).withRootElement(root).withRecordClass(T.class).withCharset(Charset)` — **these four are the ONLY builder methods on `XmlIO.Write`.**
  - **Write Limitations — do NOT invent methods here**: `XmlIO.Write` has **no** `withSuffix`, **no** `withNumShards`, and **no** `withShardTemplate`. It always emits `{prefix}-0000i-of-0000n.xml`; the `.xml` suffix is hardcoded internally and is not configurable. If a node specifies `suffix`, `numShards` or `shardTemplate` and those values cannot be honored, either leave them unset (when `suffix` is already `.xml`, the default output already satisfies it) or switch to the `FileIO` composition, which does support them: `FileIO.<T>write().via(XmlIO.sink(T.class).withRootElement(root).withCharset(cs)).to(dir).withNaming(FileIO.Write.defaultNaming(prefix, suffix)).withNumShards(n)`.
- **`HadoopFileSystem`** (`hdfs://` paths):
  - Required Imports: `org.apache.beam.sdk.io.hdfs.HadoopFileSystemOptions`, `org.apache.hadoop.conf.Configuration`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-hadoop-file-system` plus `org.apache.hadoop:hadoop-client` and `org.apache.hadoop:hadoop-hdfs` at runtime.
  - There is NO `HadoopFileSystem` read/write transform. HDFS is a **filesystem registrar**: read and write with the ordinary file connector named by the node's `format` property (`TextIO`, `ParquetIO`, `AvroIO`, ...) pointed at an `hdfs://` path. The Hadoop config is supplied through `PipelineOptions`, not through the transform builder.
  - Options wiring: the custom options interface MUST extend `HadoopFileSystemOptions`, which contributes `List<Configuration> getHdfsConfiguration()` / `setHdfsConfiguration(List<Configuration>)`.
  - `configurationResources`: build a `Configuration` and `conf.addResource(new Path(eachResource))` for each comma-separated path, then `options.setHdfsConfiguration(Collections.singletonList(conf))`.
  - **Not expressible through Beam**: `hdfsUser`, `authMechanism`, `replicationFactor` and `blockSize` have NO Beam API. They are Hadoop `Configuration` keys — set `dfs.replication` and `dfs.blocksize` on the `Configuration` object, and the user via the `HADOOP_USER_NAME` environment variable in the runner scripts. Configure them that way rather than dropping them.
- **`IcebergIO`** (Apache Iceberg tables) — reach it through **Managed I/O**, not through a bespoke builder:
  - Required Imports: `org.apache.beam.sdk.managed.Managed`, `org.apache.beam.sdk.values.PCollectionRowTuple`, `org.apache.beam.sdk.values.Row`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-managed` and `org.apache.beam:beam-sdks-java-io-iceberg`, plus the catalog implementation the node's `catalogType` names (e.g. `org.apache.iceberg:iceberg-hive-metastore` for `hive`, `org.apache.hadoop:hadoop-client` for `hadoop`).
  - An `org.apache.beam.sdk.io.iceberg.IcebergIO` class does exist, but `IcebergIO.writeRows` is `@Internal`. **Always generate the Managed form.**
  - Source (Read): `PCollectionRowTuple.empty(pipeline).apply("ReadIceberg", Managed.read(Managed.ICEBERG).withConfig(config)).get("output")` → `PCollection<Row>`. The output tag is the literal string `"output"`.
  - Sink (Write): `PCollectionRowTuple.of("input", rows).apply("WriteIceberg", Managed.write(Managed.ICEBERG).withConfig(config))`. The input tag is `"input"`; the returned tuple's tag is `"snapshots"` (not `"output"`). The input must be a `PCollection<Row>` with a schema — convert beforehand if the upstream element type is not `Row`.
  - **Config keys are snake_case and are VALIDATED at construction**: Managed rejects an unrecognized key with a pipeline construction failure, so never invent one.
    - Read keys: `table`, `catalog_name`, `catalog_properties`, `config_properties`, `keep`, `drop`, `filter`.
    - Write keys: `table`, `catalog_name`, `catalog_properties`, `config_properties`, `triggering_frequency_seconds`, `keep`, `drop`, `only`, `partition_fields`, `table_properties`, `sort_fields`, `autosharding`, `direct_write_byte_limit`, `using_side_input_table_cache`, `polling_buckets`.
  - **Node property → config key mapping** (panel properties are camelCase; the config map is not): `table` → `table`; `catalogName` → `catalog_name`; `columnProjection` → `keep` (as a `List<String>`, splitting the comma-separated value); `partitionFields` → `partition_fields` (`List<String>`); `triggeringFrequencySeconds` → `triggering_frequency_seconds` (`Integer`); `tableProperties` → `table_properties` (`Map<String, String>` parsed from the `key=value` lines). `catalogType`, `warehouseLocation` and `catalogUri` are NOT top-level keys — they go **inside** `catalog_properties` as `type`, `warehouse` and `uri` respectively.
  - **Keys that do NOT exist — never emit them**: there is no `write_mode` and no `create_table_if_not_exists`. Managed Iceberg writes are **append-only**, and a missing table is created from the incoming schema unconditionally. Do not attempt to simulate `overwrite` or `upsert`.
- **`TikaIO`**:
  - Required Imports: `org.apache.beam.sdk.io.tika.TikaIO`, `org.apache.beam.sdk.io.tika.ParseResult`, `org.apache.beam.sdk.io.FileIO`, `org.apache.beam.sdk.io.Compression`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-tika`.
  - **Source (Read) Composition Rule**: `TikaIO.parse().filepattern(filePattern)` has **NO** `.with*` builder methods (`withTikaConfigPath`, `withContentTypeHint`, `withInputMetadata` live on `TikaIO.ParseFiles`, NOT `TikaIO.Parse`, and `withParseSynchronously` was removed after Beam 2.2). Therefore, whenever `tikaConfigPath`, `contentTypeHint`, `inputMetadata`, or non-auto `compression` is specified, you MUST compose: `pipeline.apply(FileIO.match().filepattern(filePattern)).apply(FileIO.readMatches().withCompression(compression)).apply(TikaIO.parseFiles().withTikaConfigPath(...).withContentTypeHint(...).withInputMetadata(...))`.
  - **Sink (Write)**: There is **NO** `TikaIO.write()` class in Apache Beam. A `SINK` node with `beam_transform: TikaIO` persists formatted string payloads using `TextIO.write().to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)` (note the method is `.withShardNameTemplate`, never `.withShardTemplate`).
- **`ThriftIO`**:
  - Required Imports: `org.apache.beam.sdk.io.thrift.ThriftIO`, `org.apache.beam.sdk.io.FileIO`, `org.apache.thrift.protocol.TBinaryProtocol`, `org.apache.thrift.protocol.TCompactProtocol`, `org.apache.thrift.protocol.TJSONProtocol`, `org.apache.thrift.protocol.TSimpleJSONProtocol`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-thrift` and `org.apache.thrift:libthrift`.
  - **Source (Read) Composition Rule**: `ThriftIO` has no standalone `read().from(...)`; it exposes `ThriftIO.readFiles(T.class).withProtocol(protocolFactory)`. Always compose `pipeline.apply(FileIO.match().filepattern(filePattern)).apply(FileIO.readMatches().withCompression(compression)).apply(ThriftIO.readFiles(T.class).withProtocol(protocolFactory))`. **Protocol Restriction**: `TSimpleJSONProtocol` is write-only — `ThriftIO.ReadFiles.withProtocol` explicitly throws `IllegalArgumentException("TSimpleJSONProtocol is a write only protocol")` if passed `new TSimpleJSONProtocol.Factory()`. Never emit `TSimpleJSONProtocol` on read.
  - **Sink (Write)**: Compose `FileIO.<T>write().via(ThriftIO.sink(protocolFactory)).to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards)`. Neither `ThriftIO.sink` nor `FileIO.Write` has `withRecordClass` or `withShardTemplate`.
- **`ContextualTextIO`**:
  - Required Imports: `org.apache.beam.sdk.io.contextualtextio.ContextualTextIO`, `org.apache.beam.sdk.values.Row`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-contextual-text-io` (it is in its own artifact, NOT `beam-sdks-java-core`).
  - **Source (Read)**: `ContextualTextIO.read().from(filePattern).withDelimiter(delimiterBytes).withHasMultilineCSVRecords(bool).withCompression(compression).withEmptyMatchTreatment(treatment)`. `.withHintMatchesManyFiles()` and `.withRecordNumMetadata()` are **no-arg** methods — chain them only when `true` (never emit `withHintMatchesManyFiles(false)`).
  - **Stale Javadoc Trap**: `ContextualTextIO.Read.watchForNewFiles(...)` does **NOT** exist (upstream Javadoc Example 3 is broken). For `watchForNewFilesInterval`, pass `.withMatchConfiguration(FileIO.MatchConfiguration.create(treatment).continuously(org.joda.time.Duration.standardSeconds(interval), Watch.Growth.afterTimeSinceNewOutput(org.joda.time.Duration.standardHours(1))))`.
  - **Emitted `Row` Schema**: Fields are `value` (`STRING`), `resourceId` (LogicalType over nested `Row{resource, is_directory}` — **never** `row.getString("fileName")`, which throws), `recordOffset` (`INT64`), `recordNumInOffset` (`INT64`), `rangeOffset` (`INT64`), and nullable `recordNum` (`INT64`, always null unless `.withRecordNumMetadata()` was called).
  - **Sink (Write)**: `ContextualTextIO` has **NO** `write()` or `sink()` API in Apache Beam. For a `SINK` node with `beam_transform: ContextualTextIO`, emit `TextIO.write().to(to).withSuffix(suffix).withDelimiter(delimiter.toCharArray()).withHeader(header).withFooter(footer).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)` (note `TextIO.Write.withDelimiter` takes `char[]`, whereas `ContextualTextIO.Read.withDelimiter` takes `byte[]`).
- **`CsvIO`**:
  - Required Imports: `org.apache.beam.sdk.io.csv.CsvIO`, `org.apache.beam.sdk.io.TextIO`, `org.apache.commons.csv.CSVFormat`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-csv` and `org.apache.commons:commons-csv`.
  - **Source (Read) Composition & Header Rule**: `CsvIO.parseRows(schema, csvFormat)` (or `CsvIO.parse(T.class, csvFormat)`) is a `PTransform<PCollection<String>, CsvIOParseResult<...>>`, NOT a file source. Always compose `pipeline.apply(TextIO.read().from(filePattern)).apply(CsvIO.parseRows(schema, csvFormat)).getOutput()`. **Hard Validation Constraint**: `CsvIOParseHelpers.validateCsvFormat` **requires** a non-null, non-empty `.withHeader(col1, col2, ...)` on `CSVFormat` and throws `IllegalArgumentException` if `skipHeaderRecord`, `ignoreHeaderCase`, `allowDuplicateHeaderNames`, or `allowMissingColumnNames` is enabled on the `CSVFormat`.
  - **Sink (Write)**: `CsvIO.writeRows(to, csvFormat).withSuffix(suffix).withCompression(compression).withNumShards(numShards)`.
- **`JsonIO`**:
  - Required Imports: `org.apache.beam.sdk.io.json.JsonIO`, `org.apache.beam.sdk.transforms.JsonToRow`, `org.apache.beam.sdk.io.TextIO`
  - Maven Dependencies: Add `org.apache.beam:beam-sdks-java-io-json`.
  - **Source (Read)**: `JsonIO` in Java is **write-only** — `JsonIO.read()` and `JsonIO.readRows()` do **NOT** exist. For a `SOURCE` node with `beam_transform: JsonIO`, emit `pipeline.apply(TextIO.read().from(filePattern).withCompression(compression)).apply(JsonToRow.withSchema(schema))`.
  - **Sink (Write)**: `JsonIO.writeRows(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards)` (or `JsonIO.<T>write(to)` for schema-registered types). Always emits newline-delimited JSON.
- **`TFRecordIO`**:
  - Required Imports: `org.apache.beam.sdk.io.TFRecordIO`, `org.apache.beam.sdk.io.Compression`
  - Source (Read): `TFRecordIO.read().from(filePattern).withCompression(compression)` (plus `.withoutValidation()` — no-arg — only when `validate` is `false`). Produces `PCollection<byte[]>` (no `.withCoder` or `.withMinBundleSize` exists on `TFRecordIO.Read`); if `coder` is specified on the node, deserialize downstream via `MapElements`.
  - Sink (Write): `TFRecordIO.write().to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)`. Consumes `PCollection<byte[]>`. **Never pass `Compression.AUTO` on write** — `Compression.AUTO.writeCompressed()` throws `UnsupportedOperationException`.
- **Filesystem Registrars (`S3FileSystem`, `AzureBlobStoreFileSystem`, `GcsFileSystem`, `LocalFileSystem`)**:
  - None of these have `.read()` or `.write()` transforms. Always read/write with the underlying format transform specified by the node's `format` property (`TextIO`, `AvroIO`, `ParquetIO`, `FileIO`) pointed at the target URI (`s3://`, `azfs://`, `gs://`, or local path).
  - **Per-Format Compression & Validation Vocabulary**:
    - Only `TextIO` and `FileIO` use `org.apache.beam.sdk.io.Compression` (`withCompression(Compression.X)`). `Compression` has **NO** `XZ` or `TAR` member, and `Compression.AUTO` / `Compression.ZIP` throw `UnsupportedOperationException` on write.
    - `AvroIO.write` uses `.withCodec(org.apache.avro.file.CodecFactory.snappyCodec() / deflateCodec(level) / bzip2Codec() / zstandardCodec(level) / xzCodec(level) / nullCodec())` — never `.withCompression(...)`.
    - `ParquetIO.sink(schema)` uses `.withCompressionCodec(org.apache.parquet.hadoop.metadata.CompressionCodecName.SNAPPY / GZIP / LZO / BROTLI / LZ4 / ZSTD / UNCOMPRESSED)`.
    - `validate: false` on `TextIO` / `AvroIO` / `ParquetIO` reads has no `withoutValidation()` at Beam 2.76 — map `validate: false` to `.withEmptyMatchTreatment(EmptyMatchTreatment.ALLOW)`.
  - **`S3FileSystem` (`s3://` paths)**: Extend `org.apache.beam.sdk.io.aws2.options.S3Options` (which extends `AwsOptions`; artifact `beam-sdks-java-io-amazon-web-services2`). Region (`setAwsRegion`), endpoint (`setEndpoint`), and credentials (`setAwsCredentialsProvider`) live on `AwsOptions`; `setS3StorageClass`, `setSSEAlgorithm` (`--SSEAlgorithm`, `@Nullable` — omit when empty/none), `setSSEKMSKeyId` (`--SSEKMSKeyId`), and `setS3UploadBufferSizeBytes` (default 64 MB, minimum 5 MB) live on `S3Options`.
  - **`AzureBlobStoreFileSystem` (`azfs://` paths ONLY)**: Artifact `org.apache.beam:beam-sdks-java-io-azure`. Registers **ONLY `azfs://{account}/{container}/{blob}`** — `AzfsResourceId.fromUri` actively throws `"Invalid AZFS URI scheme"` on `abfss://`! Never emit `abfss://` for `AzureBlobStoreFileSystem`. Options live on `org.apache.beam.sdk.io.azure.options.BlobstoreOptions` (`setAzureConnectionString`, `setSasToken`, `setAccountName` + `setAccessKey` — **both** `accountName` and `accessKey` must be set together for shared-key auth) and `AzureOptions` (`setAzureCredentialsProvider(TokenCredential)`).
  - **`GcsFileSystem` (`gs://` paths)**: Options live on `org.apache.beam.sdk.extensions.gcp.options.GcsOptions` (`setProject`, `setGcsPerformanceMetrics` (`--gcsPerformanceMetrics`), `setReadTimeoutMs`, `setWriteTimeoutMs`, `setGcsUploadBufferSizeBytes` on write).

### 4. Windowing, Utility & Dangling Outputs
- **`WindowInto`**:
  - Required Imports: `org.apache.beam.sdk.transforms.windowing.Window`, `org.apache.beam.sdk.transforms.windowing.FixedWindows`, `org.joda.time.Duration`
  - Syntax: `Window.into(FixedWindows.of(Duration.standardMinutes(minutes)))`
- **`ParseMessage`**:
  - Required Imports: `com.fasterxml.jackson.databind.ObjectMapper`, `com.fasterxml.jackson.databind.JsonNode`, `org.apache.beam.sdk.transforms.DoFn`, `org.apache.beam.sdk.values.TupleTag`, `org.apache.beam.sdk.values.TupleTagList`, `org.apache.beam.sdk.values.PCollectionTuple`
  - Tagged Outputs: If downstream edges connect to `valid` and `error` handles, implement a static nested `DoFn` declaring `TupleTag<T> VALID_TAG = new TupleTag<T>() {};` (where `T` is `TableRow` for BigQuery or `String`/`Map`) and `TupleTag<String> ERROR_TAG = new TupleTag<String>() {};`. Apply via `ParDo.of(new ParseMessageDoFn()).withOutputTags(VALID_TAG, TupleTagList.of(ERROR_TAG))`.
  - **GENERIC JSON PARSING RULE (CRITICAL)**: When parsing JSON into `TableRow` (for BigQuery) and NO explicit schema is defined in `codeGenerationPrompt` or `system_instructions`, **ALWAYS parse all JSON fields generically**:
    ```java
    JsonNode root = mapper.readTree(message);
    TableRow row = new TableRow();
    if (root.isObject()) {
        root.fields().forEachRemaining(entry -> {
            JsonNode val = entry.getValue();
            row.set(entry.getKey(), val.isValueNode() ? val.asText() : val.toString());
        });
    }
    ```
    **NEVER** hardcode specific field names (such as `bucket`, `name`, `size`, `timeCreated`) based on topic or subscription names!
- **`LogMessage`**:
  - Syntax: `MapElements.into(TypeDescriptors.strings()).via((String x) -> { org.slf4j.LoggerFactory.getLogger("Pipeline").info("Log: {}", x); return x; })`
- **`Flatten`**:
  - Syntax: `PCollectionList.of(pcoll1).and(pcoll2).apply(Flatten.pCollections())`
- **`Reshuffle`**:
  - Syntax: `Reshuffle.of()`
- **Global Fallback Rule**: If a transform requires a function argument that the node's properties and instructions do not specify, generate an identity/pass-through implementation with a `// TODO:` comment. Never invent business logic.
- **Dangling Branches**: If a node produces a `PCollection` that no downstream edge consumes, append a simple logging step so the branch terminates cleanly in a sink.

  - Use `.withDelimiter(byte[])`, `.withCompression(Compression.<TYPE>)`, `.withEmptyMatchTreatment(EmptyMatchTreatment.<TYPE>)`, and `.withHintMatchesManyFiles()`.
- **Jackson Dependency Alignment**: Explicitly declare `com.fasterxml.jackson.core:jackson-core`, `jackson-databind`, and `jackson-annotations` version `2.15.3` (or higher) in `pom.xml` to avoid runtime `NoClassDefFoundError: StreamReadConstraints`.
- **Datafaker (mock / synthetic data generation)**: When the pipeline generates mock data with Datafaker, pin `<groupId>net.datafaker</groupId><artifactId>datafaker</artifactId><version>2.7.0</version>`. The date API changed between releases, so the pinned version and the called method MUST agree:
  - `faker.timeAndDate()` returns `net.datafaker.providers.base.TimeAndDate`; `past(long, TimeUnit)` returns `java.time.Instant`, whose `toString()` is ISO-8601 (`2025-03-12T10:15:30Z`). This accessor does NOT exist in Datafaker 2.1.0 and calling it there fails with `cannot find symbol: method timeAndDate()`.
  - `faker.date()` returns `net.datafaker.providers.base.DateAndTime`; `past(int, TimeUnit)` returns `java.sql.Timestamp`, whose `toString()` is space-separated (`2025-03-12 10:15:30.123`), NOT ISO-8601.
  - Prefer `faker.timeAndDate()` for any value written as a timestamp to BigQuery, because ISO-8601 is the canonical literal format. Do NOT mix: `timeAndDate()` requires the 2.7.0 pin above.
- **Testing & Hamcrest Dependencies**: Include `org.hamcrest:hamcrest:2.2` at compile/runtime scope (do NOT place Hamcrest under `<scope>test</scope>` because Beam's SparkRunner registers `TestSparkPipelineOptions` which requires `org.hamcrest.Matcher` at runtime when `PipelineOptionsFactory` initializes). Unit testing dependencies like `junit:junit:4.13.2` and `org.junit.vintage:junit-vintage-engine:${junit.version}` can be under `<scope>test</scope>`.
- **Maven Shade Plugin Output & Filters**: Set `<outputFile>${project.build.directory}/main.jar</outputFile>` in `maven-shade-plugin`. Always configure `<filter><artifact>*:*</artifact><excludes><exclude>META-INF/*.SF</exclude><exclude>META-INF/*.DSA</exclude><exclude>META-INF/*.RSA</exclude></excludes></filter>` (with no spaces in `*:*`) to strip signed JAR digests and prevent `SecurityException: Invalid signature file digest`.
- **Coders**: Avoid returning `PCollection<Map<String, Object>>` without an explicit coder. Use `.setCoder(...)` or Beam `Row` schema (`PCollection<Row>`).
- **BigQueryIO Return Type**: `BigQueryIO.readTableRows()` returns `BigQueryIO.TypedRead<TableRow>`, NOT `TypedRead<String>`.
- **PipelineOptions in Flex Templates**: Declare standard primitive/String getters and setters (e.g. `String getJobId(); void setJobId(String value);`). Do NOT use `ValueProvider<T>` as it is legacy Classic template API.
- **JdbcIO Write Statement Placeholders**: When using `withStatement(...)` with `JdbcIO.<T>write()`, always ensure the number of columns in the SQL statement, the number of `?` placeholders, and the parameters set in `PreparedStatementSetter` (index 1 to N) match 1-to-1.
- **Side Output Emission**: Use `c.output(tag, value)` in `DoFn.ProcessContext`.

## 7. Final Self-Review Checklist
Before outputting the final JSON `files` array, verify:
1. No literal `{{...}}` placeholder remains in any generated file.
2. Every runtime variable uses the identical camelCase name in the `PipelineOptions` interface, `metadata.json`, and all three runner scripts.
3. No `PipelineOptions` getter uses a reserved name (`jobId`, `jobName`, `project`, `tempLocation`, `gcpTempLocation`, `runner`, `appName`).
4. All imports are present; all dependency versions strictly match the pinned versions in `pom.xml`.
5. `pom.xml` is well-formed XML and includes `beam-sdks-java-io-google-cloud-platform`.
6. Every `?` in a JDBC SQL statement has a matching index in `PreparedStatementSetter`.
7. Every transform step name in `.apply("<step_name>", ...)` is globally unique.
8. Java class name, filename, Dockerfile main class, and `-Dexec.mainClass` all match in PascalCase.
9. No hardcoded credentials: No database passwords, tokens, or sensitive credentials appear as string literals in Java source code or as `@Default.String(...)` annotations on password getters. Runner scripts must NOT use hardcoded fallback strings for secrets (use `: "${DB_PASSWORD:?Error: ...}"`).
10. Container Hardening & Dockerfile Non-Root Guidance: Dockerfile base images use explicit pinned version tags (e.g. `:1.1`), never mutable `:latest`. The generated `Dockerfile` MUST include non-root least-privilege guidance—either an active non-root user (`USER 1000:1000`) or the documented commented non-root instructions (`# RUN chown ...` / `# USER 1000:1000`) to prevent root privilege escalation.
11. AvroIO Source Schemas: When an AvroIO source specifies `avroSchema` or schema path in its properties, always read Avro records using that configured schema (e.g. `new Schema.Parser().parse(...)` with the configured schema path/resource), and never substitute or conflate it with a downstream sink or intermediate projection schema.
12. Java Import and Type Disambiguation: Never use Python/Kotlin-style import aliasing ('import ... as ...') in Java source files, as the 'as' keyword is illegal in Java import statements. When disambiguating between identically named classes across packages (such as 'java.time.Duration' vs. 'org.joda.time.Duration' or 'java.time.Instant' vs. 'org.joda.time.Instant'), import one canonical class and use fully-qualified type names (e.g. 'java.time.Duration.ofSeconds(...)') inline at point of use.
13. KafkaIO Configuration: When configuring `KafkaIO.read()`, ensure all specified YAML node properties are mapped to the reader configuration. If `groupId` or `kafkaGroupId` is specified, configure the consumer group ID using `.withConsumerConfigUpdates(ImmutableMap.of(ConsumerConfig.GROUP_ID_CONFIG, "<groupId>"))` or `.updateConsumerProperties(Map.of("group.id", "<groupId>"))`.
14. Distinct Queue Parameters: When generating AWS SqsIO/SnsIO transforms where a pipeline reads from an SQS queue (or SNS SQS subscription) and writes to an SQS queue, ensure distinct pipeline options are declared and bound (e.g. `sourceQueueUrl` vs `targetQueueUrl`). Never bind the sink target queue URL to the source reader transform.
15. Specification Conformance & Transform Properties: **Walk the `properties` map of EVERY node in the input YAML and account for each key individually before emitting the file.** Each property MUST either (a) be bound to an argument or builder method on that node's transform, (b) be structurally implied by the code you generated (for example `table` becoming the argument of `.from(...)`), or (c) if the Beam API genuinely offers no way to express it, be surfaced as a `// NOTE: <property> = <value> is not configurable through <Transform>` comment on the transform. **Silently dropping a configured property is a defect** — it is the single most common failure in generated pipelines. Declaring a property in `PipelineOptions` without also passing it to the transform does NOT count as binding it. Frequently-missed examples:
    - If `batchSize` is specified on sink nodes (such as SqsIO, PubsubIO, or JdbcIO), call `.withBatchSize(...)` or appropriate batching method.
    - If `outputParallelization: true` (or `false`) is configured on a `JdbcIO` source node, call `.withOutputParallelization(true/false)`.
    - If `autosharding: true` is configured on a `JdbcIO` sink node, call `.withAutoSharding()`.
    - If `useEOS: true` is configured on a `KafkaIO` sink node, call `.withEOS(numShards, sinkGroupId)`.
    - If `maxNumRecords` or `maxReadTime` is configured on an `SqsIO` source node, call `.withMaxNumRecords(...)` / `.withMaxReadTime(...)`.
    - If `minBundleSize`, `compression`, `numShards`, `shardTemplate`, `charset` or `suffix` is configured on a file-based source or sink, chain the corresponding builder method.
16. Deterministic Container Image Tagging: In `cloudbuild.yaml` and runner scripts (`run_dataflowrunner.sh`, `run_sparkrunner.sh`), avoid using bare mutable `:latest` tags alone. In `cloudbuild.yaml`, default substitution `_TAG` to `'${SHORT_SHA}'` (never `'latest'`). In runner scripts, default container image tags to a parameterized or deterministic tag variable (e.g., `:${IMAGE_TAG:-latest}`) to guarantee build reproducibility and artifact provenance.
17. IO Parameterization via PipelineOptions: Input locations (`filePattern`, `from`, source globs) and output locations (`to`, output prefixes, destination directories) MUST be declared in the `PipelineOptions` interface with their YAML values provided via `@Default.String(...)`, and MUST also be listed as parameters in `metadata.json` so a deployed Flex Template can be repointed without rebuilding. Every OTHER non-sensitive property — including BigQuery tables, Pub/Sub topics, Kafka topics, queue URLs, SQL queries, batch sizes and codecs — stays hardcoded in the transform call per §3A. Do not parameterize the whole property map.
18. GroupIntoBatches Sharding: When preparing unkeyed elements for `GroupIntoBatches`, distribute elements across shards using a keying function (e.g., assigning a random integer key `ThreadLocalRandom.current().nextInt(numShards)` or deterministic hash) rather than using a single static key like `null` or a constant string, preventing worker partition hotspotting.
19. Shell Script Variable Quoting: In all runner scripts (`run_directrunner.sh`, `run_dataflowrunner.sh`, `run_sparkrunner.sh`), double-quote all variable references (e.g. `"$JAR_PATH"`, `"$PROJECT_ID"`, `"$IMAGE_TAG"`) to prevent word-splitting and execution errors on paths containing spaces.
20. DLQ Logging vs Dead-Letter Storage: When routing failures to a Dead Letter Queue (DLQ), always route the complete original message (or error record containing the raw payload) to the DLQ sink for re-processing. However, when logging error details via application logging (e.g. `LOG.error()`), log only the error message, exception, and record ID/metadata—never dump unredacted raw message payloads to standard log streams to prevent PII and credential leakage.
21. Multi-Line Command Integrity: In all runner scripts (`run_directrunner.sh`, `run_dataflowrunner.sh`, `run_sparkrunner.sh`), ensure every intermediate line of multi-line shell commands ends with an explicit continuation backslash (`\`) to prevent syntax errors under `set -euo pipefail`.
22. Subnetwork Flag Propagation: When `SUBNETWORK` is defined or `jobConfig.subnetwork` is specified in YAML, ensure `--subnetwork "https://www.googleapis.com/compute/v1/projects/${PROJECT_ID}/${SUBNETWORK}"` is passed in `run_dataflowrunner.sh`.
23. Unit Test Fixture & Execution Integrity: When generating unit tests:
    - Verify that test assertions and matchers strictly match the exact mock data values, keys, and types produced by the pipeline transforms given the test input fixtures. Never alter mock keys or values between input fixtures and expected assertion matchers.
    - When testing custom DoFn classes or element parsers, ensure the test actually applies the transform (`ParDo.of(new CustomDoFn())` or calls the parsing method) to synthetic input data in the `TestPipeline` instead of trivially asserting identity on `Create.of(expectedRecords)` without executing the transformation logic.
24. `.dockerignore` is generated to exclude `.git`, `target`, and `*.log` from the Docker build context.
25. Syntactic Completeness: Every generated Java file must be brace-balanced and complete. Before emitting a file, confirm each `{` has a matching `}` — including the **closing brace of the outer class**, which is the one most often truncated when a file ends with a long nested `DoFn` or anonymous class. A file that is short by even one brace fails the build outright, regardless of how correct the pipeline logic is. The same applies to unclosed parentheses in long builder chains and unterminated string literals.
