### Java SDK Syntax & Behavioral Reference:

#### 1. Sources & Sinks (I/O Connectors)
- **`PubSubIO`**:
  - Source: `PubsubIO.readStrings().fromSubscription(...)` / `fromTopic(...)`
  - Sink: `PubsubIO.writeStrings().to(...)`
- **`BigQueryIO`**:
  - Source: `BigQueryIO.readTableRows().from(...)` / `.fromQuery(...)`
  - Sink: `BigQueryIO.writeTableRows().to(...)`
- **`TextIO`**:
  - Required Imports: `org.apache.beam.sdk.io.TextIO`, `org.apache.beam.sdk.io.Compression`, `org.apache.beam.sdk.io.fs.EmptyMatchTreatment`
  - Source: `TextIO.read().from(filePattern)` (supports `.withCompression(Compression.<TYPE>)`, `.withEmptyMatchTreatment(EmptyMatchTreatment.<TREATMENT>)`, `.withDelimiter(byte[])`, `.withSkipHeaderLines(int)`, `.withHintMatchesManyFiles()`)
  - Sink: `TextIO.write().to(destinationPrefix)` (supports `.withSuffix(...)`, `.withNumShards(...)`, `.withoutSharding()`, `.withCompression(Compression.<TYPE>)`, `.withHeader(...)`, `.withFooter(...)`)
- **`FileIO`**:
  - Required Imports: `org.apache.beam.sdk.io.FileIO`, `org.apache.beam.sdk.io.Compression`, `org.apache.beam.sdk.io.fs.EmptyMatchTreatment`, `org.joda.time.Duration`
  - Match Source (`FileIO.match` / `FileIO.matchAll`): `FileIO.match().filepattern(filePattern)` (supports `.withEmptyMatchTreatment(EmptyMatchTreatment.<TREATMENT>)`, `.continuously(Duration.standardMinutes(...), Watch.Growth.never())`)
  - Read Matches Step (`FileIO.readMatches`): `FileIO.readMatches()` (produces `PCollection<FileIO.ReadableFile>`, supports `.withCompression(Compression.<TYPE>)`, `.withDirectoryTreatment(FileIO.ReadMatches.DirectoryTreatment.<TREATMENT>)`)
  - Sink (`FileIO.write`): `FileIO.<T>write().to(destinationDir)` (supports `.withPrefix(...)`, `.withSuffix(...)`, `.withCompression(Compression.<TYPE>)`, `.withNumShards(...)`, `.withIgnoreEmptyFiles(...)`)
- **`Create`**:
  - Source: `Create.of([...])`
- **`JdbcIO`**:
  - Required Imports: `org.apache.beam.sdk.io.jdbc.JdbcIO`
  - Maven Dependencies:
    - Always add `org.apache.beam:beam-sdks-java-io-jdbc` to `pom.xml`.
    - Automatically add the corresponding database driver dependency to `pom.xml` based on the selected `driverClassName` / JDBC URL:
      - PostgreSQL (`org.postgresql.Driver`): `<groupId>org.postgresql</groupId><artifactId>postgresql</artifactId><version>42.7.3</version>`
      - MySQL (`com.mysql.cj.jdbc.Driver`): `<groupId>com.mysql</groupId><artifactId>mysql-connector-j</artifactId><version>8.3.0</version>`
      - Microsoft SQL Server (`com.microsoft.sqlserver.jdbc.SQLServerDriver`): `<groupId>com.microsoft.sqlserver</groupId><artifactId>mssql-jdbc</artifactId><version>12.6.1.jre11</version>`
      - Oracle (`oracle.jdbc.driver.OracleDriver`): `<groupId>com.oracle.database.jdbc</groupId><artifactId>ojdbc11</artifactId><version>23.3.0.23.09</version>`
      - SQLite (`org.sqlite.JDBC`): `<groupId>org.xerial</groupId><artifactId>sqlite-jdbc</artifactId><version>3.45.2.0</version>`
      - Apache Derby (`org.apache.derby.jdbc.ClientDriver`): `<groupId>org.apache.derby</groupId><artifactId>derbyclient</artifactId><version>10.16.1.1</version>`
  - Query vs Table Selection (Mutually Exclusive):
    - When `selectType` is `table` or `tableName` is provided in properties:
      - Use `JdbcIO.readRows().withDataSourceConfiguration(...).withTable(tableName)` (e.g., if `tableName` is `myUsers`, generate `.withTable("myUsers")`).
      - Strictly use `.withTable(tableName)`. Do NOT use `.withQuery(...)` and do NOT invent custom schemas or `SELECT *` query strings.
    - When `selectType` is `query` or `query` is provided in properties:
      - Use `JdbcIO.readRows().withDataSourceConfiguration(...).withQuery(query)`.
      - Do NOT use `.withTable(...)`.
  - Source (Read):
    - Table Name:
      `JdbcIO.readRows().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withTable(tableName)` (supports `.withFetchSize(int)`, `.withOutputParallelization(boolean)`)
    - SQL Query:
      `JdbcIO.readRows().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withQuery(query)` (supports `.withFetchSize(int)`, `.withOutputParallelization(boolean)`) or `JdbcIO.<T>read().withDataSourceConfiguration(...).withQuery(...).withRowMapper(...)`
  - Sink (Write):
    - When `selectType` is `statement` or `statement` is provided:
      `JdbcIO.<T>write().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withStatement(statement).withPreparedStatementSetter(...)` (supports `.withBatchSize(long)`, `.withAutoSharding()`)
      - **CRITICAL SQL & PREPARED STATEMENT SETTER ALIGNMENT RULE**: The SQL statement column list (e.g. `INSERT INTO table (col1, col2) VALUES (?, ?)`) MUST have the exact same number of `?` placeholders as the number of columns listed. If the input statement in the YAML has mismatched placeholders relative to columns (e.g., 3 columns with only 2 `?` placeholders), normalize the `?` placeholders to match the column count exactly.
      - The `PreparedStatementSetter` lambda/method MUST set every single positional parameter `1` through `N` matching each `?` placeholder in the SQL statement.
    - When `selectType` is `table` or `tableName` is provided:
      `JdbcIO.<T>write().withDataSourceConfiguration(JdbcIO.DataSourceConfiguration.create(driverClassName, url).withUsername(username).withPassword(password)).withStatement("INSERT INTO " + tableName + " (col1, col2) VALUES (?, ?)").withPreparedStatementSetter(...)` (supports `.withBatchSize(long)`, `.withAutoSharding()`)

## Language SDK Best Practices & Gotchas

### Java Projects
- **Strict XML Syntax (`pom.xml`)**: Ensure strictly valid XML without stray characters.
- **IO Dependencies**: Include `org.apache.beam:beam-sdks-java-core` (provides `TextIO` and `FileIO`), `org.apache.beam:beam-sdks-java-io-google-cloud-platform` (provides `PubsubIO` and `BigQueryIO`), and `joda-time:joda-time:2.10.10` in `pom.xml`.
- **TextIO & FileIO Method Names**:
  - Use `TextIO.read().from(...).withSkipHeaderLines(n)` (the method is named `.withSkipHeaderLines(int)`, NOT `.skipHeaderLines(int)`).
  - Use `.withDelimiter(byte[])`, `.withCompression(Compression.<TYPE>)`, `.withEmptyMatchTreatment(EmptyMatchTreatment.<TYPE>)`, and `.withHintMatchesManyFiles()`.
- **Jackson Dependency Alignment**: Explicitly declare `com.fasterxml.jackson.core:jackson-core`, `jackson-databind`, and `jackson-annotations` version `2.15.3` (or higher) in `pom.xml` to avoid runtime `NoClassDefFoundError: StreamReadConstraints`.
- **Testing Dependencies**: Include `junit:junit:4.13.2`, `org.hamcrest:hamcrest:2.2`, `org.hamcrest:hamcrest-library:2.2`, and `org.junit.vintage:junit-vintage-engine:${junit.version}` under `<scope>test</scope>`.
- **Maven Shade Plugin Output**: Set `<outputFile>${project.build.directory}/main.jar</outputFile>` in `maven-shade-plugin` so `target/main.jar` is predictable for Docker copying.
- **Coders**: Avoid returning `PCollection<Map<String, Object>>` without an explicit coder. Use `.setCoder(...)` or Beam `Row` schema (`PCollection<Row>`).
- **BigQueryIO Return Type**: `BigQueryIO.readTableRows()` returns `BigQueryIO.TypedRead<TableRow>`, NOT `TypedRead<String>`.
- **PipelineOptions in Flex Templates**: Declare standard primitive/String getters and setters (e.g. `String getJobId(); void setJobId(String value);`). Do NOT use `ValueProvider<T>` as it is legacy Classic template API.
- **JdbcIO Write Statement Placeholders**: When using `withStatement(...)` with `JdbcIO.<T>write()`, always ensure the number of columns in the SQL statement, the number of `?` placeholders, and the parameters set in `PreparedStatementSetter` (index 1 to N) match 1-to-1.
- **Side Output Emission**: Use `c.output(tag, value)` in `DoFn.ProcessContext`.
