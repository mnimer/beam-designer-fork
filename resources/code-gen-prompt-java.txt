## 2. Credentials, Runtime Options & Parameterization

### Credential Handling Rules (Global — Applies to Every Connector)
Inspect every node's `properties` for authentication settings. Never emit both Secret Manager resolution and `PipelineOptions` password getters for the same credential (if a `*Secret` property is present, ignore any plaintext sibling).

1. **Secret Manager Reference (`authMode: secretManager` or any property whose name ends in `Secret`, such as `passwordSecret`, `accessKeySecret`, `tokenSecret`, `apiKeySecret`, or `secretName` / `secretId`)**:
   - The property value is the short Secret Manager secret ID, NOT the credential itself.
   - Required imports: `com.google.cloud.secretmanager.v1.SecretManagerServiceClient`, `com.google.cloud.secretmanager.v1.SecretVersionName`; add Maven dependency `com.google.cloud:google-cloud-secretmanager`.
   - Define a helper `private static String accessSecret(String projectId, String secretId) throws IOException` that opens `try (SecretManagerServiceClient client = SecretManagerServiceClient.create())` and returns `client.accessSecretVersion(SecretVersionName.of(projectId, secretId, "latest")).getPayload().getData().toStringUtf8()`.
   - Resolve the secret ONCE at pipeline construction time in `main` using `options.getProject()`, never inside a `DoFn` (`SecretManagerServiceClient` is not serializable and `DoFn` runs per element).

2. **Parameterized `PipelineOptions` Credentials (when plaintext `password`, `username`, or connection secrets appear in YAML without `*Secret`)**:
   - **Zero-Plaintext Mandate**: NEVER embed plaintext passwords, tokens, or secrets as string literals in Java source code, and NEVER annotate password getters with `@Default.String(...)`.
   - Expose credentials on the custom `PipelineOptions` interface without defaults on passwords (e.g. `getSourceDbUsername()`/`setSourceDbUsername(String)`, `getSourceDbPassword()`/`setSourceDbPassword(String)`, `getSinkDbPassword()`/`setSinkDbPassword(String)`), pass them from `options` into the transform, and declare them in `metadata.json` with `"isOptional": false` and `"isSecret": true`.
   - In runner scripts (`run_directrunner.sh`, `run_dataflowrunner.sh`, `run_sparkrunner.sh`), NEVER provide hardcoded fallback strings for passwords (`PASSWORD=${PASSWORD:-'secret'}` is forbidden). Enforce presence via `: "${SOURCE_DB_PASSWORD:?Error: SOURCE_DB_PASSWORD environment variable must be set}"`.

3. **Redacted Placeholders**:
   - If a property value is `__REDACTED_BY_BEAM_DESIGNER__`, never emit that literal; read from `System.getenv("<UPPER_SNAKE_PROP>")` with a comment that the operator must supply it.

### B. Runtime Options vs. Hardcoded Configuration
- **DEPLOYMENT-VARYING PROPERTIES MUST BE RUNTIME OPTIONS**: Because the pipeline is packaged as a Dataflow Flex Template, expose the following on the `PipelineOptions` interface (with `@Default.String(...)` for non-secrets) AND as parameters in `metadata.json` AND in all three runner scripts:
  1. **Input locations** — `filePattern`, `from`, and source paths/globs.
  2. **Output locations** — `to`, output path prefixes, and destination directories.
  3. All variables declared under `runtimeVariables` in YAML (converted to `camelCase`, e.g. `NUM_OBJECTS_PER_ITERATION` -> `getNumObjectsPerIteration()`).
  4. Parameterized credentials (per §2.A.2 above).
- **Runtime Variable Interpolation**: Replace any `${VAR_NAME}` token inside node properties or instructions with `options.get<VarNameCamelCase>()`. Never hardcode the default value of an interpolated `${VAR_NAME}`.
- **Hardcode Everything Else**: All remaining non-sensitive node properties — JDBC driver classes, SQL queries, table names, fetch/batch sizes, delimiters, charsets, compression codecs, shard counts, window durations, BigQuery tables, Pub/Sub topics, Kafka topics, and queue URLs — MUST be hardcoded directly in the transform builder calls. When a pipeline both reads from and writes to SQS/SNS queues, bind distinct `sourceQueueUrl` and `targetQueueUrl` values.
- **Reserved Option Name Safety & Remapping**:
  - NEVER declare `jobId`, `jobName`, `project`, `tempLocation`, `gcpTempLocation`, `runner`, or `appName` on a custom `PipelineOptions` interface (declaring `getJobId()` causes a fatal `IllegalArgumentException` on `DataflowWorkerHarnessOptions`).
  - Remap `JOB_ID` / `job_id` to `pipelineJobId` (`getPipelineJobId()` / `setPipelineJobId(String)`) across `PipelineOptions`, `metadata.json`, `run_directrunner.sh`, `run_dataflowrunner.sh`, and `run_sparkrunner.sh`.
  - When a node property (e.g. `jobId: beam_hadoop_write_001`) shares semantic identity with a declared `runtimeVariables` entry (e.g. `JOB_ID`), ensure the runtime option getter default in `PipelineOptions` aligns with the explicit node property value if specific, or document the precedence explicitly in comments.
  - Always use standard typed getters/setters on `PipelineOptions`; NEVER use `ValueProvider<T>` (legacy Classic template API).

## 3. Pipeline Architecture & Execution Rules

### A. Property Completeness Mandate
- **Walk the `properties` map of EVERY node in the input YAML and account for each key individually before emitting the file.** Each property MUST either:
  1. Be bound to an argument or builder method on that node's transform,
  2. Be structurally implied by the generated code (e.g. `table` becoming `.from(table)`), OR
  3. If the Beam Java SDK genuinely offers no builder method for it, be documented on the transform with `// NOTE: <property> = <value> is not configurable through <Transform>`.
- **Silently dropping a configured property is a defect.** Declaring a property on `PipelineOptions` without passing it to the transform does NOT count as binding it.

### B. Transform Selection & Node Instructions
- **Built-in Transforms First**: For any node whose `beam_transform` maps to a native Beam `PTransform` in §4, use that built-in transform. Write a custom `static` nested `DoFn` class or lambda ONLY when:
  1. `beam_transform` is `ParDo` or `ParseMessage`,
  2. The node specifies custom logic in `data.system_instructions` or `data.properties.codeGenerationPrompt` (or `prompt`), OR
  3. A built-in transform requires a user-supplied function (`Filter.by`, `MapElements.via`, `WithKeys.of`, `JdbcIO.PreparedStatementSetter`/`RowMapper`, or type-bridging adapters).
- Treat `system_instructions` and `codeGenerationPrompt` as implementation specifications — generate Java code fulfilling them and never emit them as string literals or comment stubs.
- **No Schema Guessing**: Unless explicit fields are given in `system_instructions` or `codeGenerationPrompt`, always parse JSON payloads generically across all fields (`JsonNode.fields()` into `TableRow` or `Map`). Never guess field names (like `bucket`, `name`, `size`, `timeCreated`) from topic or table names.

### C. Edge Type Alignment, Step Naming & Multi-Output Routing
- **End-to-End Edge Type Compatibility ($T_{in} \rightarrow T_{out}$)**: Inspect every edge's upstream output type and downstream expected input type (`TableRow` for `BigQueryIO`, `KV<K, V>` for `KafkaIO` and `GroupByKey`/`GroupIntoBatches`, `GenericRecord` for `ParquetIO`/`AvroIO`, `Row` for `CsvIO`/`JsonIO`/Managed `IcebergIO`, `String` for `TextIO`/`PubsubIO.writeStrings`, `byte[]` for `MqttIO`/`TFRecordIO`). Insert a bridging step (`MapElements` or `ParDo`) whenever an edge connects incompatible types, and always provide an explicit coder or `Row` schema if using `Map<String, Object>`.
- **Globally Unique Step Names**: Always pass `data.label` as the first argument to `.apply("<label>", ...)`. If multiple nodes share a label, append a qualifier (e.g. `"Filter (node_2)"`).
- **Multi-Output Tagging & DLQ Logging**: For branching nodes (`ParseMessage` or DLQ routing), declare `static final TupleTag<T>` instances and apply `ParDo.of(...).withOutputTags(validTag, TupleTagList.of(errorTag))`, emitting side outputs via `c.output(errorTag, value)`. Route the full original payload to the DLQ sink, but in `LOG.error(...)` log only the exception message and record ID/metadata — never dump unredacted raw payloads to standard logs.
- **Dangling Outputs, Streaming & Import Disambiguation**:
  - Append a logging step to any node with no outgoing edge.
  - Pass `--streaming=true` in `run_directrunner.sh` when unbounded sources (`PubsubIO`, `KafkaIO`, `MqttIO`, `PeriodicImpulse`, unbounded `GenerateSequence`) are present.
  - Never use import aliasing syntax in Java source files (the `as` keyword in import statements, e.g., `import pkg.Class as Alias;`, is invalid Java syntax and causes compilation failure). When resolving class name collisions between packages (such as `AvroCoder` or `Instant`/`Duration`), import one class or omit top-level imports and use fully-qualified class names inline (e.g., `org.apache.beam.sdk.extensions.avro.coders.AvroCoder`).

### D. Unit Test Separation & Syntactic Completeness
- Runner scripts must NEVER run `mvn test`. Every `@Test` method in `src/test/java/com/example/<PipelineName>Test.java` MUST validate output elements using `PAssert.that(...)` prior to calling `p.run().waitUntilFinish()` — never emit test methods that execute transforms without verifying the resulting `PCollection`.
- Every generated `.java` file must be 100% brace-balanced and parenthesis-balanced, including the final closing `}` of the outer class.

## 4. Connector & Transform Reference

### A. Step & PTransform Node Mapping
Use standard `org.apache.beam.sdk` transforms for these `STEP` `beam_transform` node types:

| `beam_transform` | Beam Java SDK Transform & Notes |
|---|---|
| `Map` | `MapElements.into(TypeDescriptors.strings()).via((String x) -> ...)` — ALWAYS specify `TypeDescriptors.*` (or `new TypeDescriptor<T>() {}`). **No `.as(String)` Method on `MapElements`**: `MapElements.into(...).via(...)` has NO `.as(String)` method; always pass the step name to `.apply("StepName", MapElements.into(...).via(...))`. |
| `FlatMap` / `Filter` | `FlatMapElements.into(TypeDescriptors.*).via(...)` / `Filter.by((SerializableFunction<T, Boolean>) e -> ...)` |
| `WithTimestamps` | `WithTimestamps.of((SerializableFunction<T, org.joda.time.Instant>) e -> ...)` |
| `Keys` / `Values` / `KvSwap` / `ToString` | `Keys.create()` / `Values.create()` / `KvSwap.of()` / `ToString.elements()` (or `ToString.kvs()`) |
| `KVMapper` | `WithKeys.of((SerializableFunction<T, String>) e -> ...)` |
| `GroupByKey` / `CoGroupByKey` | `GroupByKey.create()` / `CoGroupByKey.create()` |
| `Combine` | `Combine.globally(...)` or `Combine.perKey(...)`. **Combiner Optimizations after `GroupByKey`**: When `GroupByKey` is directly followed by a reduction (`Sum`, `Mean`, `Min`, `Max`), prefer `Combine.groupedValues(...)` (e.g. `Combine.groupedValues(Sum.ofDoubles())`) or `Combine.perKey(...)` rather than manual loop iteration. |
| `GroupIntoBatches` | Distribute unkeyed elements across shards first (`ThreadLocalRandom.current().nextInt(numShards)` — never a single static key) before `GroupIntoBatches.ofSize(batchSize)` |
| `BatchElements` | `BatchElements.of()` |
| `Count` / `Distinct` / `Reshuffle` | `Count.perElement()` (or `.perKey()`, `.globally()`) / `Distinct.create()` / `Reshuffle.of()` |
| `Sum` / `Mean` / `Min` / `Max` / `Latest` | `Sum.integersPerKey()` (or `doublesPerKey()`, `globally()`), `Mean`, `Min`, `Max`, `Latest` |
| `Top` / `Sample` / `ApproximateQuantiles` | `Top.largest(n)` / `Sample.fixedSizeGlobally(n)` / `ApproximateQuantiles.globally(numQuantiles)` |
| `WindowInto` | `Window.into(FixedWindows.of(org.joda.time.Duration.standardMinutes(minutes)))` |
| `Flatten` | `PCollectionList.of(pcoll1).and(pcoll2).apply(Flatten.pCollections())` |
| `LogMessage` | `MapElements.into(TypeDescriptors.strings()).via((String x) -> { LoggerFactory.getLogger("Pipeline").info("Log: {}", x); return x; })` |

### B. Source & Sink Connector Reference
- **`Create`**: `Create.of(Arrays.asList(...))`.
- **`GenerateSequence` & `PeriodicImpulse`**:
  - Bounded `GenerateSequence`: `GenerateSequence.from(start).to(stop)`. Unbounded: `GenerateSequence.from(start).withRate(elementsPerPeriod, org.joda.time.Duration.standardSeconds(periodSeconds))`.
  - `PeriodicImpulse`: `PeriodicImpulse.create().startAt(Instant.now()).withInterval(Duration.standardSeconds(intervalSeconds))`.
- **`PubsubIO`**: Source `PubsubIO.readStrings().fromTopic(...)` (or `.fromSubscription(...)`); Sink `PubsubIO.writeStrings().to(...)` (bind `.withMaxBatchSize(...)` / `.withMaxBatchBytesSize(...)` if configured).
- **`BigQueryIO`**: Source `BigQueryIO.readTableRows().from(...)` (or `.fromQuery(...)`; returns `TypedRead<TableRow>`, NOT `TypedRead<String>`); Sink `BigQueryIO.writeTableRows().to(tableSpec).withCreateDisposition(CreateDisposition.CREATE_NEVER).withWriteDisposition(WriteDisposition.WRITE_APPEND)`.
- **`TextIO`**: Source `TextIO.read().from(filePattern).withSkipHeaderLines(n)` (method is `.withSkipHeaderLines`, NOT `.skipHeaderLines`; supports `.withCompression(...)`, `.withEmptyMatchTreatment(...)`, `.withDelimiter(byte[])`, `.withHintMatchesManyFiles()`); Sink `TextIO.write().to(prefix).withSuffix(".txt")`.
- **`FileIO`**: Source `FileIO.match().filepattern(pattern).withEmptyMatchTreatment(...)` -> `FileIO.readMatches()`; Sink `FileIO.<T>write().to(dir).withSuffix(...)`.
- **`ParquetIO` & `AvroIO`**:
  - `ParquetIO`: `org.apache.beam.sdk.io.parquet.ParquetIO`, Maven deps `org.apache.beam:beam-sdks-java-io-parquet` and `org.apache.parquet:parquet-avro:1.13.1`. Read via `ParquetIO.read(schema).from(filePattern)`; write via `FileIO.<GenericRecord>write().via(ParquetIO.sink(schema).withCompressionCodec(CompressionCodecName.SNAPPY)).to(dir).withSuffix(".parquet")`.
  - `AvroIO`: `org.apache.beam.sdk.io.AvroIO`, Maven deps `org.apache.beam:beam-sdks-java-extensions-avro` (moved out of `beam-sdks-java-core` in Beam 2.50+) and `org.apache.avro:avro:1.11.3`. Read via `AvroIO.readGenericRecords(AVRO_SCHEMA).from(filePattern)`; write via `AvroIO.writeGenericRecords(AVRO_SCHEMA).to(to).withSuffix(suffix).withNumShards(numShards).withShardNameTemplate(shardTemplate).withCodec(CodecFactory.snappyCodec())`.
  - **MANDATORY `SchemaBuilder` RULE — NO MULTI-LINE JSON SCHEMA STRINGS**: Whenever defining an inline Avro `Schema` (for `AvroIO`, `ParquetIO`, or filesystem registrars), ALWAYS construct a `static final Schema` constant (or initialize once in `@Setup`/constructor, never per-element inside `@ProcessElement`) using `org.apache.avro.SchemaBuilder`: `SchemaBuilder.record("Record").namespace("com.example").fields().requiredString("id").requiredString("payload").endRecord()`. Keep source and sink schemas distinct when both exist, and NEVER embed multi-line raw JSON schema strings (`"{\n  \"type\": ..."`).
- **`JdbcIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-jdbc` plus driver (`org.postgresql:postgresql:42.7.3`, `com.mysql:mysql-connector-j:8.3.0`, `com.microsoft.sqlserver:mssql-jdbc:12.6.1.jre11`, `com.oracle.database.jdbc:ojdbc11:23.3.0.23.09`, `org.xerial:sqlite-jdbc:3.45.2.0`, `org.apache.derby:derbyclient:10.16.1.1`).
  - Source: `JdbcIO.readRows().withDataSourceConfiguration(...).withTable(tableName)` (or `.withQuery(query)`). Chain `.withOutputParallelization(true/false)` if `outputParallelization` is configured, and `.withFetchSize(int)` if `fetchSize` is configured.
  - Sink: `JdbcIO.<T>write().withDataSourceConfiguration(...).withStatement(sql).withPreparedStatementSetter(...)`. Chain `.withAutoSharding()` if `autosharding: true`, and `.withBatchSize(long)` if `batchSize` is configured. Ensure the number of `?` placeholders in `sql` matches the `PreparedStatementSetter` parameters (1..N) 1-to-1.
- **`KafkaIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-kafka` and `org.apache.kafka:kafka-clients:3.6.1`.
  - Source: `KafkaIO.<String, String>read().withBootstrapServers(...).withTopic(...).withKeyDeserializer(StringDeserializer.class).withValueDeserializer(StringDeserializer.class).withoutMetadata()`. Bind `groupId` / `kafkaGroupId` via `.withConsumerConfigUpdates(ImmutableMap.of(ConsumerConfig.GROUP_ID_CONFIG, groupId))`.
  - Sink: `KafkaIO.<String, String>write().withBootstrapServers(...).withTopic(...).withKeySerializer(StringSerializer.class).withValueSerializer(StringSerializer.class)`.
  - **Exactly-Once Semantics (`useEOS`)**: When `useEOS: true` (or `eos: true`) is specified on a `KafkaIO` sink node, you MUST enable EOS by calling `.withEOS(numShards > 0 ? numShards : 1, sinkGroupId != null ? sinkGroupId : "eos-sink-group")` or `.withProducerConfigUpdates(Map.of(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, "true"))`. NEVER silently omit EOS when specified in YAML.
- **`SnsIO` & `SqsIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-amazon-web-services2` plus `software.amazon.awssdk:sns:2.25.16` / `software.amazon.awssdk:sqs:2.25.16`.
  - `SnsIO` is write-only (`SnsIO.write().to(topicArn)`). On `SqsIO.read().withQueueUrl(queueUrl)`, chain `.withMaxNumRecords(long)` and `.withMaxReadTime(org.joda.time.Duration)` (Joda `Duration`, not `java.time.Duration`) when configured.
- **`MqttIO`**:
  - Maven dep: `org.apache.beam:beam-sdks-java-io-mqtt`. Use `MqttIO.ConnectionConfiguration.create(serverUri, topic).withClientId(clientId).withUsername(username).withPassword(password)`.
- **`AmqpIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-amqp` and `org.apache.qpid:proton-j`. Read via `AmqpIO.read().withAddresses(addresses)`; write via `AmqpIO.write().withAddresses(addresses)`. When `username` and/or `password` (or Secret Manager password) are configured, incorporate credentials into the AMQP connection URI (e.g. `amqp://[username]:[password]@[host]:[port]/[address]` or `amqps://[username]:[password]@[host]:[port]/[address]`) rather than omitting them from the URI after Secret Manager resolution.
- **`XmlIO`**:
  - Required Imports: `org.apache.beam.sdk.io.xml.XmlIO`, `org.apache.beam.sdk.io.Compression`, `javax.xml.bind.annotation.*`.
  - Maven Dependencies: `org.apache.beam:beam-sdks-java-io-xml`, `jakarta.xml.bind:jakarta.xml.bind-api:2.3.3` (exports `javax.xml.bind`), and `org.glassfish.jaxb:jaxb-runtime:2.3.3`.
  - Source: `XmlIO.<T>read().from(filePattern).withRootElement(root).withRecordElement(record).withRecordClass(T.class)` (supports `.withCharset(Charset)`, `.withCompression(Compression)`, `.withMinBundleSize(long)`).
  - Sink: `XmlIO.<T>write().to(filenamePrefix).withRootElement(root).withRecordClass(T.class).withCharset(Charset)` — **these four are the ONLY builder methods on `XmlIO.Write`.** `XmlIO.Write` has **no** `withSuffix`, **no** `withNumShards`, and **no** `withShardTemplate` (`.xml` suffix is hardcoded).
  - Custom Naming/Sharding Escape Hatch: If `suffix`, `numShards`, or `shardTemplate` must be customized, compose `FileIO.<T>write().via(XmlIO.sink(T.class).withRootElement(root).withCharset(cs)).to(dir).withNaming(FileIO.Write.defaultNaming(prefix, suffix)).withNumShards(n)`.
- **`HadoopFileSystem`** (`hdfs://` paths):
  - Maven deps: `org.apache.beam:beam-sdks-java-io-hadoop-file-system`, `org.apache.hadoop:hadoop-client`, `org.apache.hadoop:hadoop-hdfs`.
  - HDFS is a **filesystem registrar**: read/write with the format connector (`TextIO`, `ParquetIO`, `AvroIO`) pointed at `hdfs://`. Extend `HadoopFileSystemOptions` on `PipelineOptions`, load `configurationResources` into `org.apache.hadoop.conf.Configuration`, set `dfs.replication` and `dfs.blocksize` on `Configuration`, and set `HADOOP_USER_NAME` in runner scripts.
- **`IcebergIO`** (Apache Iceberg tables — reach through **Managed I/O**):
  - Required Imports: `org.apache.beam.sdk.managed.Managed`, `org.apache.beam.sdk.values.PCollectionRowTuple`, `org.apache.beam.sdk.values.Row`.
  - Maven deps: `org.apache.beam:beam-sdks-java-managed`, `org.apache.beam:beam-sdks-java-io-iceberg`, plus catalog artifact (`org.apache.iceberg:iceberg-hive-metastore` or `org.apache.hadoop:hadoop-client`).
  - Source: `PCollectionRowTuple.empty(pipeline).apply("ReadIceberg", Managed.read(Managed.ICEBERG).withConfig(config)).get("output")` → `PCollection<Row>`. The output tag is the literal string `"output"`.
  - Sink: `PCollectionRowTuple.of("input", rows).apply("WriteIceberg", Managed.write(Managed.ICEBERG).withConfig(config))` (input tag is `"input"`, and the returned tuple's tag is `"snapshots"`, not `"output"`).
  - **Validated `snake_case` Config Keys**: Map `table` → `table`; `catalogName` → `catalog_name`; `columnProjection` → `keep` (`List<String>`); `partitionFields` → `partition_fields` (`List<String>`); `triggeringFrequencySeconds` → `triggering_frequency_seconds` (`Integer`); `tableProperties` → `table_properties` (`Map<String, String>`). `catalogType`, `warehouseLocation`, and `catalogUri` are NOT top-level keys — place them inside `catalog_properties` as `type`, `warehouse`, and `uri`.
  - **Keys that do NOT exist**: there is no `write_mode` and no `create_table_if_not_exists` (Managed Iceberg writes are **append-only**).
- **`TikaIO`**:
  - Maven dep: `org.apache.beam:beam-sdks-java-io-tika`.
  - **Source Composition**: `TikaIO.parse().filepattern(filePattern)` has **NO** `.with*` builder methods (`withTikaConfigPath`, `withContentTypeHint`, `withInputMetadata` live on `TikaIO.ParseFiles`). Always compose `pipeline.apply(FileIO.match().filepattern(filePattern)).apply(FileIO.readMatches().withCompression(compression)).apply(TikaIO.parseFiles().withTikaConfigPath(configPath).withContentTypeHint(contentType).withInputMetadata(inputMeta))`.
  - **Sink**: There is **NO** `TikaIO.write()` class in Apache Beam. Persist via `TextIO.write().to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)`.
- **`ThriftIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-thrift` and `org.apache.thrift:libthrift`.
  - **Source Composition**: Compose `pipeline.apply(FileIO.match().filepattern(filePattern)).apply(FileIO.readMatches().withCompression(compression)).apply(ThriftIO.readFiles(T.class).withProtocol(protocolFactory))`. `TSimpleJSONProtocol` is write-only (`ThriftIO.ReadFiles.withProtocol` throws `IllegalArgumentException("TSimpleJSONProtocol is a write only protocol")`) — Never emit `TSimpleJSONProtocol` on read.
  - **Sink**: Compose `FileIO.<T>write().via(ThriftIO.sink(protocolFactory)).to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards)`.
- **`ContextualTextIO`**:
  - Maven dep: For Source (`ContextualTextIO.read()`), add `org.apache.beam:beam-sdks-java-extensions-contextual-text-io` (NEVER `beam-sdks-java-io-contextual-text-io`, which does not exist on Maven Central).
  - **Source**: `ContextualTextIO.read().from(filePattern).withDelimiter(delimiterBytes).withHasMultilineCSVRecords(bool).withCompression(compression).withEmptyMatchTreatment(treatment)` (plus no-arg `.withHintMatchesManyFiles()` / `.withRecordNumMetadata()` only when `true`). `ContextualTextIO.Read.watchForNewFiles(...)` does **NOT** exist — use `.withMatchConfiguration(FileIO.MatchConfiguration.create(treatment).continuously(duration, terminationCondition))`. Emitted `Row` fields are `value`, `resourceId` (never `fileName`), `recordOffset`, `recordNumInOffset`, `rangeOffset`, and `recordNum`.
  - **Sink**: `ContextualTextIO` has **NO** `write()` or `sink()` API; emit `TextIO.write().to(to).withSuffix(suffix).withDelimiter(delimiter.toCharArray()).withHeader(header).withFooter(footer).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)` (`beam-sdks-java-core` only).
- **`CsvIO`**:
  - Maven deps: `org.apache.beam:beam-sdks-java-io-csv` and `org.apache.commons:commons-csv`.
  - **Source Composition Syntax**: `CsvIO.parseRows(schema, csvFormat)` returns a `PTransform<PCollection<String>, CsvIO.ParseResult>`. Apply the transform to the `PCollection<String>` first, then call `.getOutput()` on the returned `ParseResult`: `PCollection<Row> rows = pipeline.apply("ReadLines", TextIO.read().from(filePattern)).apply("ParseCsv", CsvIO.parseRows(schema, csvFormat)).getOutput();`. NEVER call `.getOutput()` directly on `CsvIO.parseRows(schema, csvFormat)` inside `.apply(CsvIO.parseRows(schema, csvFormat).getOutput())`. `CsvIOParseHelpers.validateCsvFormat` **requires** a non-null, non-empty `.withHeader(col1, col2)` on `CSVFormat` and forbids `skipHeaderRecord`, `ignoreHeaderCase`, `allowDuplicateHeaderNames`, and `allowMissingColumnNames`.
  - **Sink**: `CsvIO.writeRows(to, csvFormat).withSuffix(suffix).withCompression(compression).withNumShards(numShards)`.
- **`JsonIO`**:
  - Maven dep: `org.apache.beam:beam-sdks-java-io-json`.
  - **Source**: `JsonIO` in Java is **write-only** (`JsonIO.read()` does not exist). Emit `pipeline.apply(TextIO.read().from(filePattern).withCompression(compression)).apply(JsonToRow.withSchema(schema))`.
  - **Sink**: `JsonIO.writeRows(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards)`.
- **`TFRecordIO`**:
  - Source: `TFRecordIO.read().from(filePattern).withCompression(compression)` (plus no-arg `.withoutValidation()` when `validate` is `false`).
  - Sink: `TFRecordIO.write().to(to).withSuffix(suffix).withCompression(compression).withNumShards(numShards).withShardNameTemplate(shardTemplate)`. **Never pass `Compression.AUTO` on write** — `Compression.AUTO.writeCompressed()` throws `UnsupportedOperationException`.
- **Filesystem Registrars (`S3FileSystem`, `AzureBlobStoreFileSystem`, `GcsFileSystem`, `LocalFileSystem`)**:
  - Read/write with the underlying format transform (`TextIO`, `AvroIO`, `ParquetIO`, `FileIO`) pointed at `s3://`, `azfs://`, `gs://`, or local path.
  - **Compression & Validation Vocabulary**: `Compression` has **NO** `XZ` or `TAR` member (`org.apache.beam.sdk.io.Compression`), and `Compression.AUTO`/`ZIP` throw `UnsupportedOperationException` on write. Map `validate: false` on `TextIO`/`AvroIO`/`ParquetIO` reads to `.withEmptyMatchTreatment(EmptyMatchTreatment.ALLOW)`.
  - **`S3FileSystem` (`s3://` paths)**: Extend `org.apache.beam.sdk.io.aws2.options.S3Options` (`beam-sdks-java-io-amazon-web-services2`). **CRITICAL `S3Options` GETTER COLLISION RULE**: Because `AwsOptions` already declares `Region getAwsRegion()` / `void setAwsRegion(Region)`, NEVER declare `String getAwsRegion()` / `void setAwsRegion(String)` on an interface extending `S3Options` (use `options.setAwsRegion(Region.of(regionStr))` or name custom string getters `getS3RegionName()`).
  - **`AzureBlobStoreFileSystem` (`azfs://` paths ONLY)**: Artifact `org.apache.beam:beam-sdks-java-io-azure`. Registers **ONLY `azfs://{account}/{container}/{blob}`** — never emit `abfss://` (`AzfsResourceId.fromUri` throws `"Invalid AZFS URI scheme"`). Configure via `BlobstoreOptions` (`setAzureConnectionString`, `setSasToken`, or both `setAccountName` + `setAccessKey`).
  - **`GcsFileSystem` (`gs://` paths)**: Configure via `org.apache.beam.sdk.extensions.gcp.options.GcsOptions` (`setGcsPerformanceMetrics`, `setReadTimeoutMs`, `setWriteTimeoutMs`, `setGcsUploadBufferSizeBytes`).
