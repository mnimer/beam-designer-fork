## 3. Core Architecture & Coding Rules

### A. Runtime Variables vs. Hardcoded Node Configuration
- **STRICT RUNTIME VARIABLES ONLY**:
  - ONLY variables explicitly declared under `runtimeVariables` in the YAML (e.g. `JOB_ID`, `NUM_OBJECTS_PER_ITERATION`) may be declared in `argparse` / `PipelineOptions`, in `metadata.json`, and as CLI arguments in runner scripts.
  - **HARDCODE ALL NODE PROPERTIES**: All node configuration values (JDBC URLs, usernames, passwords, driverClassName, SQL queries, table names, fetch/batch sizes, delimiters, file patterns, BigQuery tables, Pub/Sub topics) MUST be hardcoded directly into transform calls in Python. NEVER expose node properties as command-line arguments.
- **Reserved Option Name Safety & Remapping**:
  - **NEVER use reserved Beam/Dataflow option names**: `job_name`, `job_id`, `project`, `region`, `runner`, `temp_location`, `staging_location`, `template_location`, `streaming`, `subnetwork` are reserved by Apache Beam / Dataflow.
  - If a runtime variable is named `JOB_ID` or `job_id`, map its identifier to `pipeline_job_id` consistently across ALL artifacts:
    - `argparse` parameter: `parser.add_argument('--pipeline_job_id', ...)`
    - `metadata.json` parameter `"name"`: `"pipeline_job_id"`
    - `run_directrunner.sh` argument: `--pipeline_job_id="value"`
    - `run_dataflowrunner.sh` parameter: `pipeline_job_id="value"`
  - Convert all other runtime variables from YAML into standard snake_case (e.g. `NUM_OBJECTS_PER_ITERATION` -> `num_objects_per_iteration`).
  - For Flex Templates, use standard `parser.add_argument(...)`. **NEVER** use `parser.add_value_provider_argument(...)` (deprecated legacy Classic template API that causes runtime `TypeCheckError`).
  - Ensure that ALL runtime variables defined in YAML are supplied with default values in `run_directrunner.sh` and `run_dataflowrunner.sh`.

### B. Node Instruction Fields vs Hardcoded Config
- `data.system_instructions` and `data.properties.codeGenerationPrompt` (or `data.properties.prompt`) contain natural-language descriptions of the logic this node must implement.
  - Treat them as implementation instructions: generate Python code that fulfills them.
  - NEVER emit them as string literals, configuration values, or comment-only stubs.
  - They are EXEMPT from the "hardcode all node properties" rule.
  - If they conflict with default behaviors in the reference table below, the node's instructions win.
- **NO SCHEMA GUESSING / HALLUCINATION**: Do NOT invent, assume, or hardcode payload schema fields based on topic, subscription, dataset, or table names (for example, do NOT assume a subscription named with "object-finalize" carries specific GCS file metadata keys like `bucket`, `name`, `size`, `timeCreated`). Unless explicit schema fields are specified in `system_instructions` or `codeGenerationPrompt`, ALWAYS parse payloads generically across all fields.

### C. Runtime Variable Interpolation
- Any `${VAR_NAME}` token inside a node's properties or instructions refers to the runtime variable `VAR_NAME` from `runtimeVariables`.
- Replace it with a read of the corresponding parsed CLI argument using snake_case (e.g. `${NUM_OBJECTS_PER_ITERATION}` -> `known_args.num_objects_per_iteration`). NEVER hardcode the default value of an interpolated `${VAR_NAME}`.

### D. Custom `DoFn` Policy
- **PREFER BUILT-IN TRANSFORMS**: If a node's `beam_transform` appears in the SDK Syntax Reference below, use that built-in `PTransform`. Do NOT reimplement it as a custom `DoFn`.
- **WHEN A CUSTOM `DoFn` OR FUNCTION IS REQUIRED**: Write a custom `beam.DoFn` or function ONLY in these cases:
  1. `beam_transform` is `ParDo` or `ParseMessage` (multi-output branching parser).
  2. The node has `system_instructions` or `codeGenerationPrompt` describing custom business logic.
  3. A built-in transform requires a user-supplied callable (`beam.Filter`, `beam.Map`, `beam.FlatMap`, or adapter lambdas between built-ins).
- Define custom `beam.DoFn` classes or functions in the main pipeline module. Do NOT create separate helper source files.

### E. Type Propagation & End-to-End Edge Compatibility
- **MANDATORY EDGE TYPE ALIGNMENT**: Every edge in the input YAML connects a `source` node to a `target` node. When generating code, you MUST inspect both:
  1. **Upstream Output Type ($T_{in}$)**: The Python type emitted by the predecessor node (see Section 4).
  2. **Downstream Expected Input Type ($T_{out}$)**: The Python type consumed by the successor node (see Section 4).
- **Intermediate Transform Bridging**: Any intermediate step (`ParseMessage`, `ParDo`, `Map`, `Filter`) MUST explicitly bridge $T_{in} \rightarrow T_{out}$ to match the downstream connector's expected input type as defined in Section 4. (For example, BigQuery sinks require `dict`, Kafka sinks require `(key, value)` tuples, Parquet sinks require PyArrow record dicts, Text sinks require `str`, PubSub sinks require `bytes`, etc.).
- **Automatic Adapters for Direct Incompatible Edges**: If an edge in the YAML directly connects a source to a sink with incompatible types without an intermediate transformation (e.g. `ReadFromPubSub` producing `bytes` connected directly to `WriteToBigQuery` requiring `dict`), you MUST automatically insert a clean mapping step (such as `beam.Map` decoding and converting JSON bytes to `dict`) between them so the Python pipeline is strictly type-safe.

### F. Transform Naming & Uniqueness
- Every step name in `p | '<step_name>' >> ...` MUST be non-empty and **globally unique** across the pipeline.
- Use `data.label` as the step name. If multiple nodes share the same label or if the label equals the default transform name, append a distinct qualifier or node ID (e.g. `'Filter Valid Records (node_2)'`) to prevent `RuntimeError: A transform with label "..." already exists in the pipeline`.

### G. Streaming vs. Batch Detection
- If the pipeline contains streaming sources (`PubSubIO`, `KafkaIO`, `MqttIO`, `PeriodicImpulse`), configure the pipeline for streaming:
  - Add `options.view_as(StandardOptions).streaming = True` when initializing `PipelineOptions` or pass `--streaming` in `run_directrunner.sh`.

### H. Separation of Runner Scripts and Unit Tests
- `run_directrunner.sh` and `run_dataflowrunner.sh` MUST ONLY execute the main pipeline file (`python src/<pipeline_name>.py ... "$@"`). They must **NEVER** run unit tests (`unittest`).
- The main pipeline file `src/<pipeline_name>.py` MUST have `if __name__ == '__main__': run()` and MUST **NEVER** import `unittest` or invoke `unittest.main()`.
- Unit tests live strictly in `src/<pipeline_name>_test.py` and use Beam's `TestPipeline`, `assert_that`, and `equal_to`. Import the pipeline module using `from src.<pipeline_name> import ...` or `from <pipeline_name> import ...`.

### I. Code Documentation & Quality
- Include author and module documentation header on the main file:
  ```python
  """
  Pipeline: <PipelineName>
  Description: <Pipeline Description>
  Author: Mike Nimer <mikenimer@google.com>
  """
  ```
- Fail fast: Do NOT add undocumented fallbacks or silently swallow exceptions.

## 4. Built-in Beam Transform Syntax & Import Reference

### 1. Sources & Sinks (I/O Connectors)
- **`PubSubIO`**:
  - Required Imports: `import apache_beam as beam`
  - Source: `beam.io.ReadFromPubSub(subscription=..., topic=...)` (produces `bytes`)
  - Sink: `beam.io.WriteToPubSub(topic=...)` (consumes `bytes`)
- **`GenerateSequence`**:
  - **MANDATORY SUBSTITUTION RULE — UNBOUNDED SEQUENCES MUST BECOME `PeriodicImpulse`**:
    - There is no native Python `GenerateSequence`; cross-language (x-lang) unbounded sequences cause a permanent silent deadlock under DirectRunner because unbounded Java bundles never finish.
    - If unbounded (`sequenceMode: unbounded` or no `stop` configured): MUST generate `PeriodicImpulse(start_timestamp=time.time(), fire_interval=period_seconds)` (with `import time`, `from apache_beam.transforms.periodicsequence import PeriodicImpulse`).
    - If bounded without rate limit: MUST generate `beam.Create(range(start, stop))`.
    - If bounded with rate limit: Generate `PeriodicImpulse(start_timestamp=_start, stop_timestamp=_start + _duration, fire_interval=period_seconds)`.
    - To fan out N elements per tick: `| 'fan out' >> beam.FlatMap(lambda ts: range(elements_per_period))`.
- **`PeriodicImpulse`**:
  - Required Imports: `import time`, `from apache_beam.transforms.periodicsequence import PeriodicImpulse`
  - Unbounded: `PeriodicImpulse(start_timestamp=time.time(), fire_interval=interval_seconds)`
  - Bounded: `PeriodicImpulse(start_timestamp=time.time(), stop_timestamp=time.time() + duration_seconds, fire_interval=interval_seconds)`
- **`BigQueryIO`**:
  - Source: `beam.io.ReadFromBigQuery(query=..., table=..., use_standard_sql=True)`
  - Sink: `beam.io.WriteToBigQuery(table=..., create_disposition=beam.io.BigQueryDisposition.CREATE_NEVER, write_disposition=beam.io.BigQueryDisposition.WRITE_APPEND)` (consumes `dict` rows)
- **`TextIO`**:
  - Source: `beam.io.ReadFromText(file_pattern=..., skip_header_lines=...)`
  - Sink: `beam.io.WriteToText(file_path_prefix=..., file_name_suffix=".txt")` (consumes `str`)
- **`FileIO`**:
  - Required Import: `from apache_beam.io import fileio` (MANDATORY: `apache_beam.io` does not expose `fileio` without explicit import)
  - Match Source: `fileio.MatchFiles(file_pattern)`
  - Read Matches: `fileio.ReadMatches()` (produces `ReadableFile` elements)
  - Sink: `fileio.WriteToFiles(path=..., file_name_suffix=...)`
- **`ParquetIO`**:
  - Required Imports: `import pyarrow`, `from apache_beam.io.parquetio import ReadFromParquet, WriteToParquet`
  - Source: `ReadFromParquet(file_pattern=...)`
  - Sink: `WriteToParquet(file_path_prefix=..., schema=schema)`
- **`Create`**:
  - Source: `beam.Create([...])`
- **`JdbcIO`**:
  - Required Imports: `from apache_beam.io.jdbc import ReadFromJdbc, WriteToJdbc`
  - Driver Dependencies & `classpath`:
    - PostgreSQL (`org.postgresql.Driver`) is built into Beam's expansion service by default.
    - For all other drivers, provide the Maven coordinate via `classpath=[...]`:
      - MySQL (`com.mysql.cj.jdbc.Driver`): `classpath=["com.mysql:mysql-connector-j:8.3.0"]`
      - SQL Server (`com.microsoft.sqlserver.jdbc.SQLServerDriver`): `classpath=["com.microsoft.sqlserver:mssql-jdbc:12.6.1.jre11"]`
      - Oracle (`oracle.jdbc.driver.OracleDriver`): `classpath=["com.oracle.database.jdbc:ojdbc11:23.3.0.23.09"]`
      - SQLite (`org.sqlite.JDBC`): `classpath=["org.xerial:sqlite-jdbc:3.45.2.0"]`
      - Apache Derby (`org.apache.derby.jdbc.ClientDriver`): `classpath=["org.apache.derby:derbyclient:10.16.1.1"]`
  - Source (Read):
    - When `selectType` is `table`: `ReadFromJdbc(driver_class_name=..., jdbc_url=..., username=..., password=..., table_name=..., classpath=...)`
    - When `selectType` is `query`: `ReadFromJdbc(driver_class_name=..., jdbc_url=..., username=..., password=..., query=..., classpath=...)`
  - Sink (Write):
    - `WriteToJdbc(driver_class_name=..., jdbc_url=..., username=..., password=..., statement=statement, classpath=...)`
    - **CRITICAL SQL & TUPLE ALIGNMENT RULE**: The SQL statement column list (e.g. `INSERT INTO table (col1, col2) VALUES (?, ?)`) MUST have the exact same number of `?` placeholders as columns. The upstream transform preceding `WriteToJdbc` MUST emit a `tuple` whose element count and order match the `?` placeholders 1-to-1.
- **`KafkaIO`**:
  - Required Imports: `from apache_beam.io.kafka import ReadFromKafka, WriteToKafka`
  - Source (Read): `ReadFromKafka(consumer_config={'bootstrap.servers': bootstrap_servers, 'group.id': group_id, 'auto.offset.reset': 'latest'}, topics=[topic])`
  - Sink (Write): `WriteToKafka(producer_config={'bootstrap.servers': bootstrap_servers}, topic=topic)` (consumes `(key, value)` tuples)
- **`SnsIO`**:
  - Required Imports: `from apache_beam.transforms.external import ExternalTransform, ImplicitSchemaPayloadBuilder, BeamJarExpansionService`
  - Sink (Write): Use cross-language Java expansion transform targeting `beam:transform:org.apache.beam:aws2_sns_write:v1`.
  - *Note*: `SnsIO` is write-only. If a node specifies SNS as a source, ingest via an SQS subscription queue (`ReadFromSqs` via `ExternalTransform`) or bridged GCP Pub/Sub topic (`ReadFromPubSub`).
- **`SqsIO`**:
  - Required Imports: `from apache_beam.transforms.external import ExternalTransform, ImplicitSchemaPayloadBuilder, BeamJarExpansionService`
  - Source (Read): Cross-language transform `beam:transform:org.apache.beam:sqs_read:v1`.
  - Sink (Write): Cross-language transform `beam:transform:org.apache.beam:sqs_write:v1`.
- **`MqttIO`**:
  - Required Imports: `from apache_beam.transforms.xlang.io import ReadFromMqtt, WriteToMqtt`
  - Source (Read): `ReadFromMqtt(server_uri=..., topic=...)` (produces `bytes`)
  - Sink (Write): `WriteToMqtt(server_uri=..., topic=...)` (consumes `bytes`)

### 2. Element-Wise Transforms
- **`WithTimestamps`**:
  - Syntax: `beam.Map(lambda x: beam.window.TimestampedValue(x, time.time()))` (with `import time`). Do NOT use `beam.WithTimestamps()`.
- **`Map`**: `beam.Map(lambda x: ...)`
- **`FlatMap`**: `beam.FlatMap(lambda x: ...)`
- **`Filter`**: `beam.Filter(lambda x: True)`
- **`Keys`**: `beam.Keys()`
- **`Values`**: `beam.Values()`
- **`KVMapper`**: `beam.Map(lambda x: (x.get('id', 'default_key'), x))`
- **`KvSwap`**: `beam.KvSwap()`
- **`ToString`**: `beam.ToString.Element()` or `beam.ToString.KVs()`

### 3. Aggregations & Combining
- **`Count`**: `beam.combiners.Count.PerElement()`, `beam.combiners.Count.PerKey()`, `beam.combiners.Count.Globally()`
- **`GroupByKey`**: `beam.GroupByKey()`
- **`GroupIntoBatches`**: `beam.GroupIntoBatches(batch_size)`
- **`CoGroupByKey`**: `beam.CoGroupByKey()`
- **`Combine`**: `beam.CombineGlobally(...)` or `beam.CombinePerKey(...)`
- **`Distinct`**: `beam.Distinct()`
- **`Max`**: `beam.CombinePerKey(max)` or `beam.CombineGlobally(max)`
- **`Min`**: `beam.CombinePerKey(min)` or `beam.CombineGlobally(min)`
- **`Mean`**: `beam.combiners.Mean.PerKey()`, `beam.combiners.Mean.Globally()`
- **`Sum`**: `beam.combiners.Sum.PerKey()`, `beam.combiners.Sum.Globally()`
- **`Latest`**: `beam.combiners.Latest.PerKey()`, `beam.combiners.Latest.Globally()`
- **`Sample`**: `beam.combiners.Sample.FixedSizeGlobally(n)`, `beam.combiners.Sample.FixedSizePerKey(n)`
- **`Top`**: `beam.combiners.Top.Of(n)`, `beam.combiners.Top.PerKey(n)`
- **`BatchElements`**: `beam.BatchElements(min_batch_size=..., max_batch_size=...)`
- **`ApproximateQuantiles`**: `from apache_beam.transforms.stats import ApproximateQuantiles`, `ApproximateQuantiles.Globally(num_quantiles)`

### 4. Windowing, Utility & Dangling Outputs
- **`WindowInto`**:
  - Required Imports: `from apache_beam import window`
  - Syntax: `beam.WindowInto(window.FixedWindows(size_in_seconds))`
- **`ParseMessage`**:
  - Required Imports: `import json`, `from apache_beam import pvalue`
  - Tagged Outputs: If downstream edges connect to `valid` and `error` handles, implement a `beam.DoFn`:
    ```python
    class ParseMessageDoFn(beam.DoFn):
        def process(self, element):
            try:
                # Handle bytes or string payload
                msg_str = element.decode('utf-8') if isinstance(element, bytes) else str(element)
                data = json.loads(msg_str)
                # Generic JSON Parsing: emit data dictionary directly
                yield pvalue.TaggedOutput('valid', data)
            except Exception as e:
                yield pvalue.TaggedOutput('error', {'error': str(e), 'raw': str(element)})
    ```
    Apply via `p | 'Parse Message' >> beam.ParDo(ParseMessageDoFn()).with_outputs('valid', 'error')`.
  - **GENERIC JSON PARSING RULE (CRITICAL)**: When parsing JSON (for BigQuery or general processing) and NO explicit schema is defined in `codeGenerationPrompt` or `system_instructions`, **ALWAYS parse all JSON fields dynamically into a `dict`** (`json.loads(...)`). **NEVER** hardcode specific field names (such as `bucket`, `name`, `size`, `timeCreated`) based on topic or subscription names!
- **`LogMessage`**:
  - Required Imports: `import logging`
  - Syntax: Define a passthrough logger so elements are preserved:
    ```python
    def _log_element(element):
        logging.info("Log: %s", element)
        return element

    | 'Log Message' >> beam.Map(_log_element)
    ```
  - **NEVER** use `print(...) or logging.info(...)` in a lambda because both return `None`, silently destroying downstream data.
- **`Flatten`**:
  - Syntax: `(pcoll1, pcoll2) | beam.Flatten()`
- **`Reshuffle`**:
  - Syntax: `beam.Reshuffle()`
- **Global Fallback Rule**: If a transform requires a function argument that the node's properties and instructions do not specify, generate an identity/pass-through implementation with a `# TODO:` comment. Never invent business logic.
- **Dangling Branches**: If a node produces a `PCollection` that no downstream edge consumes, append a simple logging step so the branch terminates cleanly in a sink.
