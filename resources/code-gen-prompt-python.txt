## 2. Credentials, Runtime Options & Parameterization

### Credential Handling Rules (Global — Applies to Every Connector)
Inspect every node's `properties` for authentication settings. Never emit both Secret Manager resolution and CLI password flags for the same credential (if a `*Secret` property is present, ignore any plaintext sibling).

1. **Secret Manager Reference (`authMode: secretManager` or any property whose name ends in `Secret`, such as `passwordSecret`, `accessKeySecret`, `tokenSecret`, `apiKeySecret`, or `secretName` / `secretId`)**:
   - The property value is the short Secret Manager secret ID, NOT the credential itself.
   - Required import: `from google.cloud import secretmanager`; add `google-cloud-secret-manager>=2.16.0` to `requirements.txt`.
   - Define a helper `_access_secret(project_id: str, secret_id: str, version: str = "latest") -> str` (using `# Reads the payload of a Secret Manager secret.` rather than a `"""` docstring) that calls `secretmanager.SecretManagerServiceClient().access_secret_version(request={"name": f"projects/{project_id}/secrets/{secret_id}/versions/{version}"}).payload.data.decode("UTF-8")`.
   - Resolve the secret ONCE at pipeline construction time in `run()` using `project_id` derived from pipeline options (`--project`), never inside a `DoFn` (`process` runs per element).
   - Apply this across all connectors (`JdbcIO`, `SingleStoreIO`, `PulsarIO`, `MongoDbIO`, `SnowflakeIO`, `Pyodbc`, etc.).

2. **Parameterized CLI Credentials (when plaintext `password`, `username`, or connection secrets appear in YAML without `*Secret`)**:
   - **Zero-Plaintext Mandate**: NEVER embed plaintext passwords, tokens, or secrets as string literals in Python code or as `default=` values on `parser.add_argument(...)`.
   - Expose credentials as `argparse` arguments (`required=True` for passwords, e.g. `--source_db_username`, `--source_db_password`, `--sink_db_password`, or `--db_password`), pass them from `known_args` to the transform, and declare them in `metadata.json` with `"isOptional": false` and `"isSecret": true`.
   - In runner scripts (`run_directrunner.sh`, `run_dataflowrunner.sh`), NEVER provide hardcoded fallback strings for passwords (`PASSWORD=${PASSWORD:-'secret'}` is forbidden). Enforce presence via `: "${SOURCE_DB_PASSWORD:?Error: SOURCE_DB_PASSWORD environment variable must be set}"`.

3. **Redacted Placeholders**:
   - If a property value is `__REDACTED_BY_BEAM_DESIGNER__`, never emit that literal; read from an `UPPER_SNAKE_CASE` environment variable named after the property with a comment that the operator must supply it.

### B. Runtime Options vs. Hardcoded Configuration
- **DEPLOYMENT-VARYING PROPERTIES MUST BE RUNTIME OPTIONS**: Because the pipeline is packaged as a Dataflow Flex Template, expose the following as `argparse` flags (with the YAML value as `default=` for non-secrets) AND as parameters in `metadata.json` AND in `run_directrunner.sh` / `run_dataflowrunner.sh`:
  1. **Input locations** — `filePattern`, `from`, and source paths/globs (`--input_pattern`).
  2. **Output locations** — `to`, output path prefixes, and destination directories (`--output_prefix`).
  3. All variables declared under `runtimeVariables` in YAML (converted to `snake_case`, e.g. `NUM_OBJECTS_PER_ITERATION` -> `--num_objects_per_iteration`).
  4. Parameterized credentials (per §2.A.2 above).
- **Runtime Variable Interpolation**: Replace any `${VAR_NAME}` token inside node properties or instructions with `known_args.<var_name_snake_case>`. Never hardcode the default value of an interpolated `${VAR_NAME}`.
- **Hardcode Everything Else**: All remaining non-sensitive node properties — JDBC driver classes, SQL queries, table names, fetch/batch sizes, delimiters, charsets, compression codecs, shard counts, window durations, BigQuery tables, Pub/Sub topics, Kafka topics, and queue URLs — MUST be hardcoded directly in the transform calls.
- **Reserved Option Name Safety & Remapping**:
  - NEVER register `job_name`, `job_id`, `project`, `region`, `runner`, `temp_location`, `staging_location`, `template_location`, `streaming`, or `subnetwork` on custom `argparse` parsers.
  - Remap `JOB_ID` / `job_id` to `pipeline_job_id` across `argparse` (`--pipeline_job_id`), `metadata.json` (`"name": "pipeline_job_id"`), `run_directrunner.sh`, and `run_dataflowrunner.sh`.
  - Always use `parser.add_argument(...)`. **NEVER** use `parser.add_value_provider_argument(...)` (legacy Classic template API that causes `TypeCheckError`).

## 3. Pipeline Architecture & Execution Rules

### A. Property Completeness Mandate
- **Walk the `properties` map of EVERY node in the input YAML and account for each key individually before emitting the file.** Each property MUST either:
  1. Be passed into that node's transform constructor, kwargs, or configuration dictionary,
  2. Be structurally implied by the generated code (e.g. `table` becoming `table=`), OR
  3. If the Beam Python SDK genuinely offers no parameter for it, be documented on the transform with `# NOTE: <property> = <value> is not configurable through <Transform>`.
- **Silently dropping a configured property is a defect.** Parsing a property into `argparse` without passing it to the transform does NOT count as binding it.

### B. Transform Selection & Node Instructions
- **Built-in Transforms First**: For any node whose `beam_transform` maps to a native Beam `PTransform` in §4, use that built-in transform. Write a custom `beam.DoFn` or callable ONLY when:
  1. `beam_transform` is `ParDo` or `ParseMessage`,
  2. The node specifies custom logic in `data.system_instructions` or `data.properties.codeGenerationPrompt` (or `prompt`), OR
  3. A built-in transform requires a callable (`beam.Map`, `beam.FlatMap`, `beam.Filter`, or type-bridging adapters) or no native Python connector class exists (`Pyodbc`, `SingleStoreIO`, `PulsarIO`).
- Treat `system_instructions` and `codeGenerationPrompt` as implementation specifications — generate Python code fulfilling them and never emit them as string literals or comment stubs.
- **No Schema Guessing**: Unless explicit fields are given in `system_instructions` or `codeGenerationPrompt`, always parse JSON/dict payloads generically (`json.loads(...)`). Never guess field names (like `bucket`, `name`, `size`, `timeCreated`) from topic or table names.

### C. Edge Type Alignment, Step Naming & Multi-Output Routing
- **End-to-End Edge Type Compatibility ($T_{in} \rightarrow T_{out}$)**: Inspect every edge's upstream output type and downstream expected input type (`bytes` for Pub/Sub and MQTT, `dict` for BigQuery and MongoDB, `(key, value)` tuples for Kafka and `GroupByKey`/`GroupIntoBatches`, `beam.Row` for `WriteToCsv`/`WriteToJson`/Managed Iceberg, `str` for `WriteToText`). Insert a bridging step (`beam.Map` or `ParDo`) whenever an edge connects incompatible types.
- **Globally Unique Step Names**: Use `data.label` as the step label in `p | '<label>' >> ...`. If multiple nodes share a label, append a qualifier (e.g. `'Filter (node_2)'`).
- **Tagged Outputs — NEVER wrap the main output in `TaggedOutput`**:
  - Beam routes an unrecognized tag to a null receiver and **silently discards** every element without error or warning.
  - When using `.with_outputs(TAG_ERRORS, main='valid')`, `main='valid'` only sets the *attribute name* on the returned `DoOutputsTuple` (`results['valid']`). Inside `process()`, always `yield` the main output bare and wrap only side/error outputs:
    ```python
    yield transform(element)                              # CORRECT: main output, bare
    yield TaggedOutput('valid', record)                   # WRONG: silently dropped, produces zero output
    ```
- **DLQ Routing vs. Redacted Error Logging**: Route the full original payload/error record to the Dead Letter Queue (DLQ) sink, but in application logs (`logging.warning` / `logging.error`) log only the exception message and record ID/metadata — never log unredacted raw payloads.
- **Dangling Outputs & Streaming**: Append a logging step to any node with no outgoing edge. Set `options.view_as(StandardOptions).streaming = True` (and pass `--streaming` in `run_directrunner.sh`) when unbounded sources (`PubSubIO`, `KafkaIO`, `MqttIO`, `PeriodicImpulse`) are present.

### D. Entrypoint & Unit Test Separation
- `src/<pipeline_name>.py` must end with `if __name__ == '__main__': run()` or `if __name__ == "__main__": run()` (either `if __name__ == '__main__': run()` or `if __name__ == "__main__": run()` — never mix quotation styles), and must never import `unittest`.
- `src/<pipeline_name>_test.py` imports from `src.<pipeline_name>` (or `<pipeline_name>`), applies the actual pipeline `DoFn`/transforms to synthetic inputs in `TestPipeline`, and asserts exact expected outputs with `assert_that(..., equal_to([...]))`.

## 4. Connector & Transform Reference

### A. Step & PTransform Node Mapping
Use standard `apache_beam` transforms for these `STEP` `beam_transform` node types:

| `beam_transform` | Beam Python SDK Transform & Notes |
|---|---|
| `Map` / `FlatMap` / `Filter` | `beam.Map(...)` / `beam.FlatMap(...)` / `beam.Filter(...)` |
| `Keys` / `Values` / `KvSwap` | `beam.Keys()` / `beam.Values()` / `beam.KvSwap()` |
| `KVMapper` | `beam.Map(lambda x: (x.get('id', 'default_key'), x))` |
| `ToString` | `beam.ToString.Element()` or `beam.ToString.KVs()` |
| `WithTimestamps` | `beam.Map(lambda x: beam.window.TimestampedValue(x, time.time()))` or `from apache_beam.transforms.util import WithTimestamps` (`beam.WithTimestamps` does not exist at top-level) |
| `GroupByKey` / `CoGroupByKey` | `beam.GroupByKey()` / `beam.CoGroupByKey()` |
| `GroupIntoBatches` | Key unkeyed data across shards first (`(random.randint(0, num_shards - 1), elem)` — never a single static key) before `beam.GroupIntoBatches(batch_size)` |
| `BatchElements` | `beam.BatchElements(min_batch_size=..., max_batch_size=...)` |
| `Count` / `Distinct` / `Reshuffle` | `beam.combiners.Count.PerElement()` (or `.PerKey()`, `.Globally()`) / `beam.Distinct()` / `beam.Reshuffle()` |
| `Sum` / `Mean` / `Min` / `Max` / `Latest` | `beam.combiners.Sum.PerKey()` (or `.Globally()`), `Mean`, `Latest`, `beam.CombinePerKey(min/max)` |
| `Top` / `Sample` / `ApproximateQuantiles` | `beam.combiners.Top.Of(n)` / `Sample.FixedSizeGlobally(n)` / `from apache_beam.transforms.stats import ApproximateQuantiles` |
| `WindowInto` | `beam.WindowInto(window.FixedWindows(size_in_seconds))` (with `from apache_beam import window`) |
| `Flatten` | `(pcoll1, pcoll2) | '<step_name>' >> beam.Flatten()`. Even with a single upstream edge, emit `(upstream_pcoll,) | '<step_name>' >> beam.Flatten()` so the node is never omitted. |
| `LogMessage` | Pass a helper function to `beam.Map` that calls `logging.info("Log: %s", x)` and returns `x` (never return `logging.info(...)` or `print(...)` directly, as both return `None`). |

### B. Source & Sink Connector Reference
- **`Create`**: `beam.Create([...])`.
- **`PubSubIO`**: Source `beam.io.ReadFromPubSub(subscription=..., topic=...)` (`bytes`); Sink `beam.io.WriteToPubSub(topic=...)` (`bytes`).
- **`BigQueryIO`**: Source `beam.io.ReadFromBigQuery(query=..., table=..., use_standard_sql=True)` (`dict`); Sink `beam.io.WriteToBigQuery(table=..., create_disposition=BigQueryDisposition.CREATE_NEVER, write_disposition=BigQueryDisposition.WRITE_APPEND)` (`dict`).
- **`TextIO`**: Source `beam.io.ReadFromText(file_pattern=..., skip_header_lines=...)` (`str`); Sink `beam.io.WriteToText(file_path_prefix=..., file_name_suffix=...)` (`str`).
- **`GenerateSequence` & `PeriodicImpulse`**:
  - **CRITICAL — PREFER `PeriodicImpulse` FOR PERIODIC TRIGGERS**: `GenerateSequence` in Python is a cross-language transform requiring a running **Docker daemon** and an ~800MB Java expansion JAR (which logs `KafkaIOInitializer` noise and emits nothing without Docker).
  - For periodic triggers or rate-limited sequences (`ratePerSec`, `elementsPerPeriod`), use `from apache_beam.transforms.periodicsequence import PeriodicImpulse`: `PeriodicImpulse(start_timestamp=time.time(), fire_interval=period_seconds, # seconds, NOT milliseconds)` paired with a bounded counter `DoFn` (or `beam.FlatMap`), OR if using in-memory `beam.Create(range(start, stop))` in batch mode, include `# NOTE: ratePerSec = <val> is not supported directly in in-memory beam.Create batch execution`. **NEVER silently drop or omit `ratePerSec`** or `elementsPerPeriod`.
  - Use cross-language `ExternalTransform('beam:external:java:generate_sequence:v1', ImplicitSchemaPayloadBuilder({'start': start, 'stop': stop, 'elements_per_period': elements_per_period, 'period': period_seconds * 1000}), BeamJarExpansionService('sdks:java:io:expansion-service:shadowJar'))` ONLY when the pipeline genuinely consumes the **sequence values themselves** and requires cross-language execution (`ImplicitSchemaPayloadBuilder` silently drops any key whose value is `None`).
- **`FileIO`**:
  - Required Import: `from apache_beam.io import fileio` (mandatory explicit import).
  - Source: `fileio.MatchFiles(file_pattern) | fileio.ReadMatches()`.
  - Sink: `fileio.WriteToFiles(path=..., shards=..., max_writers_per_bundle=..., file_naming=fileio.destination_prefix_naming(prefix=..., suffix=...))` — always bind `prefix` and `suffix` via `fileio.destination_prefix_naming(prefix=..., suffix=...)`. For dynamic destinations on structured dicts, use a custom `fileio.FileSink` subclass rather than stripping partition keys before `WriteToFiles`.
- **`ParquetIO`**:
  - Required Imports: `import pyarrow`, `from apache_beam.io.parquetio import ReadFromParquet, WriteToParquet`.
  - Source: `ReadFromParquet(file_pattern=..., min_bundle_size=..., validate=..., columns=[...])`.
  - Sink: `WriteToParquet(file_path_prefix=..., schema=..., codec=..., file_name_suffix=..., num_shards=..., shard_name_template=..., row_group_buffer_size=...)`.
  - **Codec Vocabulary**: `UNCOMPRESSED` maps to `codec='none'` — `'uncompressed'` is NOT a legal pyarrow value and raises `ArrowException: Unsupported compression` (valid values: `'none'`, `'snappy'`, `'gzip'`, `'lzo'`, `'brotli'`, `'lz4'`, `'zstd'`).
- **`JdbcIO`**:
  - Required Imports: `from apache_beam.io.jdbc import ReadFromJdbc, WriteToJdbc`.
  - Supply `classpath=[...]` for non-PostgreSQL drivers: MySQL `["com.mysql:mysql-connector-j:8.3.0"]`, SQL Server `["com.microsoft.sqlserver:mssql-jdbc:12.6.1.jre11"]`, Oracle `["com.oracle.database.jdbc:ojdbc11:23.3.0.23.09"]`, SQLite `["org.xerial:sqlite-jdbc:3.45.2.0"]`, Derby `["org.apache.derby:derbyclient:10.16.1.1"]`.
  - Map `outputParallelization: true` -> `output_parallelization=True`, `fetchSize` -> `fetch_size=...` on `ReadFromJdbc`, and `autosharding: true` -> `autosharding=True`, `batchSize` -> `batch_size=...` on `WriteToJdbc`.
  - Ensure every `?` placeholder in `WriteToJdbc(statement=...)` matches the upstream tuple element count 1-to-1.
- **`KafkaIO`**:
  - Required Imports: `from apache_beam.io.kafka import ReadFromKafka, WriteToKafka`.
  - Map `keySerializer` / `valueSerializer` directly to `'key.serializer'` / `'value.serializer'` in `producer_config` (never substitute `ByteArraySerializer`), and when `useEOS: true` is set, include `'enable.idempotence': 'true'` in `producer_config`.
- **`SnsIO` & `SqsIO`**:
  - Use `ExternalTransform` (`beam:transform:org.apache.beam:aws2_sns_write:v1`, `beam:transform:org.apache.beam:sqs_read:v1`, `beam:transform:org.apache.beam:sqs_write:v1`). `SnsIO` is write-only.
- **`MqttIO`**:
  - Required Imports: `from apache_beam.io.external.xlang_mqttio import WriteToMqtt, ReadFromMqtt` (or cross-language external transform; never import from `apache_beam.transforms.xlang.io`). Bind `server_uri`, `topic`, `qos`, and `retain`.
- **`MongoDbIO`**:
  - Required Imports: `import json`, `from apache_beam.io.mongodbio import ReadFromMongoDB, WriteToMongoDB`; add `pymongo>=4.0.0` to `requirements.txt`.
  - Source: `ReadFromMongoDB(uri=..., db=..., coll=..., filter=json.loads(filter_json), projection=[...], batch_size=..., bucket_auto=...)`. Account for `numSplits` with a `# NOTE:` comment when `bucket_auto` is used.
  - Sink: `WriteToMongoDB(uri=..., db=..., coll=..., batch_size=...)`. When `writeConcern` is set, append `?w=<writeConcern_lower>` to `uri` and add a `# NOTE:` comment.
- **`Pyodbc`**:
  - Add `pyodbc>=5.0.0` to `requirements.txt`.
  - **ODBC Connection String Braces Rule (CRITICAL)**: Format the driver cleanly without triple-brace f-strings (e.g. `f"DRIVER={driver};SERVER={server};PORT={port};DATABASE={database};UID={username};PWD={password}"` or `"DRIVER={" + driver + "};..."`), and resolve `passwordSecret` via `_access_secret`.
- **`SingleStoreIO` & `PulsarIO`**:
  - `SingleStoreIO`: `import singlestoredb as s2` (`singlestoredb>=1.0.0`); bind `host`, `port`, `database`, `username`, `passwordSecret` (`_access_secret`), `query` vs `table`, and `useParallelRead` / `outputParallelization`.
  - `PulsarIO`: `import pulsar` (`pulsar-client>=3.4.0`); bind `serviceUrl`, `adminUrl`, `topic`, `subscriptionName`, `startTimestamp`, `endTimestamp` on source, and `publishTimeoutMs`, `batchingEnabled`, `batchingMaxMessages`, `compressionType`, `tokenSecret` (`_access_secret`) on sink.
- **`IcebergIO` (Managed I/O)**:
  - Required Imports: `from apache_beam.transforms import managed`. There is **NO** `apache_beam.io.iceberg` module and **NO** `ReadFromIceberg` / `WriteToIceberg` class.
  - Source: `pipeline | 'ReadIceberg' >> managed.Read(managed.ICEBERG, config={...})` (`Row`). Sink: `rows | 'WriteIceberg' >> managed.Write(managed.ICEBERG, config={...})` (input must be schema'd `beam.Row` / `NamedTuple`).
  - **Validated `snake_case` Config Keys**: Map `table` → `table`; `catalogName` → `catalog_name`; `columnProjection` → `keep` (list); `partitionFields` → `partition_fields` (list); `triggeringFrequencySeconds` → `triggering_frequency_seconds` (int); `tableProperties` → `table_properties` (dict). Nest `catalogType`, `warehouseLocation`, and `catalogUri` inside `catalog_properties` (`type`, `warehouse`, `uri`) — they are NOT top-level keys.
  - **Keys that do NOT exist**: there is no `write_mode` and no `create_table_if_not_exists` (Managed Iceberg writes are **append-only**).
- **`CsvIO` & `JsonIO`**:
  - Required Imports: `from apache_beam.io.textio import ReadFromCsv, WriteToCsv, ReadFromJson, WriteToJson`.
  - **CRITICAL SCHEMA REQUIREMENT**: `WriteToCsv` and `WriteToJson` route through `WriteViaPandas` and require a schema'd `PCollection` of `beam.Row` elements (never raw `dict`s).
  - **Compression & ShardTemplate Trap**: `ReadViaPandas` / `WriteViaPandas` explicitly execute `if 'compression' in kwargs: raise NotImplementedError('compression')` and do not accept `shard_name_template=`. **Never pass `compression=`** to `ReadFromCsv` or `WriteToCsv` or `ReadFromJson` or `WriteToJson`; emit `# NOTE:` comments when `compression` or `shardTemplate` is configured, and map `numShards: 0` → `num_shards=None`.
- **`TFRecordIO`**:
  - Required Imports: `from apache_beam.io.tfrecordio import ReadFromTFRecord, WriteToTFRecord`, `from apache_beam.coders import BytesCoder, ProtoCoder`, `from apache_beam.io.filesystem import CompressionTypes`. No `min_bundle_size` kwarg or `ExampleProtoCoder` exists.
- **Filesystem Registrars (`S3FileSystem`, `AzureBlobStoreFileSystem`, `GcsFileSystem`, `LocalFileSystem` & `HadoopFileSystem`)**:
  - Read/write with the underlying format transform (`ReadFromText`/`WriteToText`, `ReadFromAvro`/`WriteToAvro`, `ReadFromParquet`/`WriteToParquet`, `fileio`) pointed at `s3://`, `azfs://`, `gs://`, `hdfs://`, or local path (`HadoopFileSystem` is a filesystem registrar: HDFS is a **filesystem registrar**, not a transform class).
  - **`S3FileSystem` (`s3://` paths)**: Configure via `apache_beam.options.pipeline_options.S3Options` (`--s3_region_name`, `--s3_endpoint_url`), add `apache-beam[gcp,aws]>=2.76.0,<3.0.0` and `boto3>=1.28.0` to `requirements.txt`, and bind or document `s3Region`, `s3StorageClass`, `sseAlgorithm`, `sseKmsKeyId`, `s3UploadBufferSizeBytes`, and `credentialsProvider`.
  - **`AzureBlobStoreFileSystem` (`azfs://` paths ONLY)**: Native via `apache_beam.options.pipeline_options.AzureOptions`. Registers **ONLY `azfs://{account}/{container}/{blob}`** — never emit `abfss://`.

Use minimum verified version bounds (`>=`) so `pip` resolves the latest compatible release without requiring manual prompt updates when libraries release new versions:
```text

pyarrow>=10.0.0
```
- Align the `apache-beam[gcp]` floor with the Dockerfile base image (`apache/beam_python3.11_sdk:2.76.0`).
- Add connector-specific packages (`google-cloud-secret-manager>=2.16.0`, `pymongo>=4.0.0`, `boto3>=1.28.0`, `pyodbc>=5.0.0`, `singlestoredb>=1.0.0`, `pulsar-client>=3.4.0`, `kafka-python>=2.0.2`) only when required by the pipeline. Never include `pyspark`.
